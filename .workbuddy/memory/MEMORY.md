# 项目长期记忆：摄影线上选片小程序

## 沟通方式（重要）
- 用户是非 Web 全栈的嵌入式工程师，**不要讲架构原理和平台机制**，只给「去哪点、填什么、怎么判断成功」的步骤清单。
- 每次交付都要明确三件事：已经做了什么 / 你要手动做什么（含具体点击路径）/ 你做完了我接着做什么。
- 先给结论和操作步骤，原因和取舍放在后面或省略。

## 方案基线
- 最终范围以 `docs/技术方案V1.2-最小闭环.md` 为准；V1.1 是决策历史。
- 当前进度：Phase 0 工程初始化（代码已写完，等用户填 AppID + 环境 ID 后验收）。
- 手工操作清单在 `docs/我要手动做的事.md`，用户按此执行。

## 关键架构决定
- 电脑端浏览器为主上传入口，小程序不上传照片（规避 9 张上限 / 无文件夹 / SD 卡读不到）。
- 原图不上云，云端只有 preview + thumbnail；ARW 永远在本地。
- 不做精修交付，微信直接发图；不做账号体系，用 openid 白名单 + token。
- 安全四道锁见 `docs/安全与访问控制.md`：数据库仅管理端可读写、发链接前校验 token、管理员用口令绑定、一码一人。
- 文件名必须与 DCIM 原名一致（JPG/ARW 同名），选片结果只需给文件名 + 缩略图，按文件名升序排序。
