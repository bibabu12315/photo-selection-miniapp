# 50 · V2 测试计划

> 本文档是**唯一测试策略来源**。
> 测试用例见 `51_TEST_CASES.md`，验收标准见 `52_ACCEPTANCE.md`，发布清单见 `53_RELEASE_CHECKLIST.md`。
>
> 本文档不追求测试覆盖率，只追求两件事：
> 1. **主链路能跑通**（`43_DEV_STATUS.md` 第七节的 8 条锚点）
> 2. **规则没被违反**（`30_BUSINESS_RULES.md` 的 BR 编号）

---

## 一、测试目标与边界

### 1.1 要测什么

| 类别 | 内容 | 依据 |
|---|---|---|
| **身份** | 网页端能否拿到正确身份、越权能否被挡 | `23_PERMISSION.md` 四道锁 |
| **规则** | 提交锁定、状态收敛、归档不回拉、套餐张数上限 | `30_BUSINESS_RULES.md` |
| **主链路** | 登录 → 建项目 → 上传 → 邀请 → 选片 → 提交 → 通知 → 导出 | `03_USER_FLOW.md` |
| **异常** | 断网、失败重试、重复提交、过期、已归档、越权 | `32_ERROR_HANDLING.md` |
| **四态** | 每个页面的 加载 / 空 / 错误 / 成功 是否都存在 | `10_PAGE_SPEC.md` 自检表 |

### 1.2 不测什么（明确排除，避免浪费时间）

- ❌ 性能压测（本产品并发在个位数，不需要）
- ❌ 浏览器兼容性矩阵（只保证 Chrome / Edge 最新版 + Safari 最新版）
- ❌ 小程序机型适配（只保证 iOS 与安卓各一台真机）
- ❌ 单元测试覆盖率（云函数是薄封装，用例级验证更划算）
- ❌ 安全渗透测试（按 `23_PERMISSION.md` 的 11 条检查清单逐条核对即可）

## 二、测试分层

| 层 | 叫什么 | 在哪做 | 验证什么 | 谁来做 |
|---|---|---|---|---|
| **L1** | 接口级 | 云开发控制台 → 云函数 → 云端测试 | 入参校验、权限拦截、错误码、数据库写入 | 开发 AI（自测） |
| **L2** | 链路级 | 真机 + 浏览器 | 端到端流程是否走通 | 你（人工） |
| **L3** | 体验级 | 真机 + 浏览器 | 四态是否齐全、反馈是否清楚、是否卡顿 | 你（人工） |

### 2.1 L1 接口级怎么测（这是能提前发现 80% 问题的一层）

微信开发者工具 → **云开发** → **云函数** → 选中函数 → **云端测试**，直接填 JSON 入参运行。

**⚠️ 关键限制（不看这条会误判）**：

云端测试**没有小程序登录态**，`getWXContext().OPENID` 返回空。所以：

| action 类型 | 云端测试能测吗 | 怎么测 |
|---|---|---|
| 不需要身份的（如 `session.createTicket`） | ✅ 能 | 直接测 |
| 需要小程序 OPENID 的 | ❌ 不能 | **必须走 L2 真机** |
| 需要 sessionToken 的 | ✅ 能 | 手动构造入参带 `sessionToken` |

**不要因为云端测试报 `ERR_NO_AUTH` 就以为是 Bug** —— 先看是不是登录态缺失导致的。

### 2.2 L2 链路级怎么测

需要**真机**。开发者工具的模拟器在以下场景与真机不一致，不能替代：

- 扫码（小程序码 / 邀请码）
- 订阅消息授权与接收
- 图片加载速度与手势缩放
- `wx.showToast` 的实际观感

### 2.3 L3 体验级怎么测

按 `10_PAGE_SPEC.md` 末尾的**四态覆盖自检表**逐页勾。缺一态视为未完工。

## 三、测试环境

### 3.1 云开发环境策略：**复用现有环境，不新建**

| 方案 | 结论 |
|---|---|
| 新建一个 test 环境 | ❌ **不采用**。云开发第二套环境要另付套餐费，得不偿失 |
| 复用现有环境 + 命名隔离 | ✅ **采用** |

**命名隔离规则**（测试期间必须遵守）：

- 所有测试项目的项目名以 `TEST-` 开头，例如 `TEST-上传链路验证`
- 测试完成后，按 `53_RELEASE_CHECKLIST.md` 第 4 节的清单**逐个删除**（删除会连带清云存储，不会留垃圾）

### 3.2 网页端部署位置

| 用途 | 位置 | 说明 |
|---|---|---|
| 开发自测 | 微信开发者工具打开 `web/` 目录 或 任意静态服务器 | 不要求域名 |
| **正式测试（必须）** | 云开发**静态托管** | 扫码登录依赖真实域名，本地 `localhost` 上微信扫码会失败 |

> **必须先在云开发控制台开通静态托管**，并把域名加进小程序「业务域名 / 服务器域名」白名单。这是 `43_DEV_STATUS.md` 里的阻塞项 B-2。

### 3.3 小程序端

- 开发者工具：用**预览**生成二维码，微信扫码在真机打开
- 提示：预览码只有开发者本人和体验成员能扫。要测「模特视角」，必须把模特微信加为**体验成员**

## 四、测试账号矩阵

**这是 V2 测试最容易卡住的地方，提前准备。**

| 角色 | 数量 | 要求 | 用途 |
|---|---|---|---|
| **摄影师 A** | 1 | 你自己的微信，且已在小程序点过「我是摄影师」 | 主账号 |
| **模特 M1** | 1 | 另一个微信号（家人 / 小号） | 主选片路径 |
| **模特 M2** | 1 | 第三个微信号 | 多人独立选片（F-13） |
| **摄影师 B** | 1 | 第四个微信号，也点「我是摄影师」 | **越权测试**（B 不能看到 A 的项目） |

**最低配置**：3 个微信号（A + M1 + B）。M2 可用 M1 的第二批项目代替，但多人独立选片就测不彻底。

> 若实在凑不到 4 个号：越权测试（TC-PERM-* ）可以在云开发控制台直接改数据库字段模拟，但会有误差，需记录为「未真机验证」。

## 五、测试数据准备

### 5.1 照片样本

| 项 | 要求 |
|---|---|
| 数量 | **30~50 张**（不要一上来就 500 张，测的是逻辑不是容量） |
| 来源 | 真实相机 JPG（A7C2 直出即可），**不要用手机截图或网络图** |
| 命名 | 保留 DCIM 原名（如 `DSC01234.JPG`），**不要重命名** |
| 文件夹 | 放一个文件夹里，用拖拽文件夹的方式上传 |

### 5.2 需要单独准备的 3 张特殊图

| 用途 | 图 |
|---|---|
| 画质对比（TC-UPLD-05） | 挑 **1 张有大面积细节**的（如毛发、织物、树叶）——糊不糊只有这类图能看出 |
| 上传失败重试（TC-EDGE-02） | 挑 **1 张体积最大**的（>10MB） |
| 格式错误（TC-EDGE-03） | 准备 **1 个非图片文件**（如 `.txt` 改名成 `.jpg`） |

### 5.3 之前的数据

- V1 遗留的测试数据：**全部删除**，不要在此基础上测（会有脏数据干扰判断）
- 具体清理动作见 `53_RELEASE_CHECKLIST.md` 第 4 节

## 七、缺陷分级

| 级别 | 判定 | 处理 |
|---|---|---|
| **S（阻塞）** | 主链路走不通 / 数据写错 / 越权能成功 / 付费资产（云存储）泄漏 | 立即停手修，修完回归全量 P0 用例 |
| **A（严重）** | 某条 BR 规则被违反，但主链路仍可走通 | 本阶段内必须修完 |
| **B（一般）** | 四态缺失、文案错误、反馈不明显 | 记入 `43_DEV_STATUS.md`，可延到 P3 |
| **C（建议）** | 观感、动画、命名 | 不阻塞发布 |

**判定归属**：`S` 与 `A` 的判定权在文档不在人 —— 只要违反 `30_BUSINESS_RULES.md` 中任一条 BR，至少是 A。

## 八、回归策略（改哪测哪，不用全测）

| 改动位置 | 必须回归的用例 |
|---|---|
| `resolveCaller` / `session` 云函数 | 全部 `TC-AUTH-*` + 全部 `TC-PERM-*` |
| `project` 云函数 | 全部 `TC-PROJ-*` + `TC-EDGE-*` 中项目类 |
| `selection` 云函数 | 全部 `TC-SEL-*` + `TC-RSLT-*` |
| `photo` 云函数 / `web/upload.js` | 全部 `TC-UPLD-*` |
| 网页端任意页面 | 该页面四态 + `TC-AUTH-02`（未登录重定向） |
| 小程序端任意页面 | 该页面四态 + `TC-PERM-*` |
| 数据库索引变更 | `TC-PROJ-04`（列表性能）+ `TC-SEL-03`（分页） |

**全量回归触发条件**（满足任一）：
- P0 阶段全部完成时
- 发布前
- 出现 S 级缺陷并修复后

## 九、测试记录方式

在 `43_DEV_STATUS.md` 的**任务状态表**里，每个任务的「测试状态」列填：

| 值 | 含义 |
|---|---|
| `未测` | 还没跑 |
| `通过` | 对应用例全绿 |
| `失败(TC-XXX-NN)` | 列出失败的用例编号 |
| `阻塞(B-x)` | 被 `43` 第三节登记的阻塞项卡住 |

**不要写「已测试」这种无信息量的词**，必须带用例编号或阻塞编号。
