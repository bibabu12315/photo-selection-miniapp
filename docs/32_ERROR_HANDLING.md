# 32 · 异常处理与错误码（V2）

> **本文档定位**：定义**每一次失败发生时，用户看到什么、系统做什么、数据处于什么状态、用户接下来能做什么**。
>
> **给 Coding Agent**：异常不是「加个 try/catch 把错吞掉」。每条异常都必须能对应到本文档某一行。
> 文档没覆盖的新异常，**照最接近的一条处理并上报补录**，不要自行发明新的交互形式。

---

## 一、分层原则

```
第 1 层  网络层      请求发不出去 / 超时 / DNS 失败     → 重试 + 提示「网络异常」
第 2 层  鉴权层      无登录态 / token 过期 / 非本人      → 引导重新登录，不重试
第 3 层  业务层      已锁定 / 超限 / 已归档 / 已过期      → 直接展示文案，不重试
第 4 层  数据层      云函数内部异常 / 数据库失败          → 记录日志 + 通用失败提示
```

**三条铁律**：
1. **技术错误不得暴露给用户**。用户永远看不到 `Error: ECONNRESET`、`errCode: -501001` 这类原始信息。
2. **可恢复的错误必须给出下一步动作**（「重试」「去续期」「联系摄影师」），不能只说「失败了」。
3. **不可恢复的错误必须说明原因**，不能只说「出错了」。

## 二、错误码表（与 `22_API.md` 1.3 一致）

| code | 含义 | 可重试 | 网页端（摄影师）文案 | 小程序摄影师端文案 | 模特端文案 |
|---|---|---|---|---|---|
| `ERR_NO_AUTH` | 无登录态 / token 失效 | ❌ | 「登录已过期，请重新扫码」→ 跳 P-W1 | 「请先进入小程序」 | 「请从摄影师分享的链接重新进入」 |
| `ERR_NOT_ADMIN` | 不是摄影师 | ❌ | 「当前微信未开通摄影师，请先在小程序引导页点『我是摄影师』」 | 同左 | — |
| `ERR_NOT_FOUND` | 资源不存在 | ❌ | 「项目不存在或已被删除」+ 返回列表 | 同左 | 「项目不存在或已被删除，请联系摄影师」 |
| `ERR_EXPIRED` | 已过期 / 票据过期 | ❌ | 「项目已过期」+ 续期按钮 | 同左 | 「该项目已过期，请联系摄影师」 |
| `ERR_LOCKED` | 已提交锁定 | ❌ | — | — | 「你已提交，如需修改请联系摄影师解锁」 |
| `ERR_LIMIT` | 超限（张数 / 模特数） | ❌ | 「最多 5 位模特」 | 同左 | 「最多可选 N 张，先取消一张」 |
| `ERR_PARAM` | 参数错误 | ❌ | 就地提示具体项（如「项目名不能为空」） | 同左 | — |
| `ERR_ARCHIVED` | 已归档 | ❌ | 「已归档，续期后可恢复」 | 同左 | 「该项目已归档，大图暂不可用」 |
| `ERR_UNKNOWN` | 未分类异常 | ✅ | 「操作失败，请重试」 | 同左 | 「加载失败，请重试」 |

> **统一返回格式**（`22_API.md` 1.2）：`{ ok: false, code, error }`；成功 `{ ok: true, data }`。
> 前端**只按 `code` 分支**，不要用 `error` 文案做判断。

## 三、异常场景矩阵

每个场景四要素：**用户看到 / 系统行为 / 数据状态 / 用户下一步**。

### 3.1 上传（网页端）

| 场景 | 用户看到 | 系统行为 | 数据状态 | 用户下一步 | code |
|---|---|---|---|---|---|
| 网络断开 | 「已暂停，等待网络恢复」+ 已传张数 | 停止排队，不再发起新请求 | 已传成功的已落库 | 恢复后点「继续」 | — |
| 单张失败（前 2 次） | 该张进度条回退，无打扰提示 | 自动重试 | 该张未登记 | 自动 | — |
| 单张失败（第 3 次） | 列表标红 | 移入失败列表 | 该张未登记 | 点「重试失败的」 | — |
| 浏览器关闭 / 刷新 | 下次进入提示「上次有 N 张未完成」 | 无自动行为 | 已成功的保留 | 继续上传 | — |
| 重复上传同一文件 | 「将覆盖 N 张同名照片」+ 确认 | 覆盖同名记录 | 同名记录更新，不新增 | 确认或取消 | — |
| 容量额度不足 | 「剩余可传 XXX 张」 | 前端拦截 + 后端校验 | 不变 | 归档旧项目或删照片 | `ERR_LIMIT` |
| 非图片文件 | 结果页列出被跳过的文件名 | 跳过，不中断整批 | 不变 | — | — |
| 上传码 / 上传票据过期 | 提示已过期，自动重新签发 | 调 `issueUploadSession` 换新 | 不变 | 自动恢复 | `ERR_EXPIRED` |
| 上传中项目被删除 | 「项目不存在或已被删除」 | 中止剩余任务 | 已传的随项目删除 | 返回列表 | `ERR_NOT_FOUND` |

### 3.2 模特选片（小程序端）

| 场景 | 用户看到 | 系统行为 | 数据状态 | 用户下一步 | code |
|---|---|---|---|---|---|
| 缩略图加载失败 | 占位图（灰色相框）+ 点击可重试 | 自动重试 1 次 | 不变 | 手动点重试 | — |
| 大图加载失败 | 「加载失败，点击重试」 | 重试 1 次 | 不变 | 手动重试 | — |
| 网络断开 | 顶部常驻「网络异常」 | 保存转本地暂存 | 云端为上次成功值 | 恢复后自动补存 | — |
| 快速连点 | 无异常 | 2s 防抖合并 | 最终态正确 | — | — |
| 自动保存失败 | 顶部「未保存，正在重试」 | 指数退避重试 | 云端为旧值 | 等待或手动重试 | — |
| 提交时网络异常 | 「提交失败，请检查网络后重试」 | 保留本地选择 | **未锁定** | 重试提交 | — |
| 重复提交（连点 / 重进） | 直接显示已提交态 | 幂等返回成功 | 已锁定 | — | — |
| 超过套餐张数上限 | 「最多可选 N 张，先取消一张」 | 前端拦截 + 后端校验 | 不变 | 取消一些再选 | `ERR_LIMIT` |
| 已提交后重新进入 | 只读查看态 + 「如需修改请联系摄影师」 | 拒绝写入 | `locked` | 联系摄影师 | `ERR_LOCKED` |
| 解锁后进入 | 「摄影师已允许你重新选择」 | — | 原选择**保留** | 增删后重交 | — |
| 项目已过期 | 「该项目已过期」+ 禁止交互 | 拦截选片与提交 | 不变 | 联系摄影师 | `ERR_EXPIRED` |
| 项目已归档 | 「已归档」+ 大图不可用 | `getPreview` 拒绝 | thumb 保留 | 联系摄影师 | `ERR_ARCHIVED` |
| 邀请码已被使用 | 「该邀请已被使用」 | 不建档 | 不变 | 向摄影师索取新码 | — |

### 3.3 项目（两端）

| 场景 | 用户看到 | 系统行为 | 数据状态 | 用户下一步 | code |
|---|---|---|---|---|---|
| 项目不存在 | 「项目不存在或已被删除」+ 返回列表 | — | — | 返回 | `ERR_NOT_FOUND` |
| 非本人项目 | 同上（**不透露项目是否存在**） | — | 不变 | — | `ERR_NOT_FOUND` |
| 项目已过期 | 「已过期」标签 | 模特端禁止选片 | 不变 | 续期（摄影师） | `ERR_EXPIRED` |
| 项目已归档 | 「已归档」 | 大图不可用 | thumb + 文件名保留 | 续期需重传 preview | `ERR_ARCHIVED` |
| 模特数达 5 | 「最多 5 位模特」 | 拒绝生成邀请 | 不变 | 移除一位再邀请 | `ERR_LIMIT` |
| 删除项目失败（部分文件删不掉） | 「已删除，个别文件清理失败（已记录）」 | **不阻断**，写日志 | 记录已删，文件可能残留 | — | — |
| 归档失败（文件删不掉） | 「归档完成，部分文件清理失败」 | 不阻断，写日志 | 状态已改 | — | — |
| 续期已归档项目 | 「已续期，需重新上传照片」 | 回 `UPLOADING` | preview 已空 | 重新上传 | — |

### 3.4 登录（网页端）

| 场景 | 用户看到 | 系统行为 | 数据状态 | 用户下一步 | code |
|---|---|---|---|---|---|
| 二维码 5 分钟未扫 | 二维码置灰 + 「已失效，点击刷新」 | 生成新 ticket | 旧 ticket → `REVOKED` | 点刷新 | `ERR_EXPIRED` |
| 扫码后轮询中网络断开 | 「网络异常，正在重试」 | 指数退避，最多 3 次 | `PENDING` | 刷新页面 | — |
| 扫了非摄影师微信 | 「该微信尚未开通摄影师」+ 引导步骤 | — | `PENDING` | 去小程序点「我是摄影师」后重扫 | `ERR_NOT_ADMIN` |
| token 过期（30 天） | 跳回登录页，不提示错误 | 清 localStorage | `REVOKED` | 重新扫码 | `ERR_NO_AUTH` |
| 退出登录 | 回到登录页 | 置 `REVOKED` + 清本地 | `REVOKED` | — | — |

### 3.5 导出（网页端）

| 场景 | 用户看到 | 系统行为 | 数据状态 | 用户下一步 |
|---|---|---|---|---|
| 项目无模特提交 | 「还没有模特提交选片」+ 空态图 | — | 不变 | 等待 |
| 剪贴板 API 不可用（非 HTTPS / 旧浏览器） | 自动选中文本 + 「请按 Ctrl+C 复制」 | 降级为选中 | 不变 | 手动复制 |
| CSV 下载失败 | 「导出失败，请重试」 | — | 不变 | 重试 |

## 四、重试与幂等策略

| 操作 | 幂等 | 重试策略 |
|---|---|---|
| `saveSelection`（自动保存） | ✅ 覆盖写 | 指数退避：1s → 2s → 4s，最多 3 次，之后挂「未保存」提示等用户操作 |
| `submitSelection` | ✅ 已锁定则直接返回成功 | **不自动重试**，失败提示用户手动重试 |
| `registerPhoto` | ✅ 按 `stem` 覆盖 | 单张最多 3 次尝试（首 + 2 自动） |
| `getPhotos` / `getResult` | ✅ 只读 | 失败重试 1 次 |
| `getPreview`（生成临时链接） | ✅ 只读 | 失败重试 1 次 |
| `project.create` | ❌ **非幂等** | **不自动重试**，失败后提示用户手动重试（避免重复建项目） |
| `project.remove` | ✅ 重复删除返回成功 | 不自动重试 |
| `resetLock` | ✅ | 不自动重试 |
| `session.claim` | ✅ 同一 ticket 只能成功一次 | 不自动重试 |

> **硬规则**：`project.create` **禁止**放在任何自动重试循环里。这是唯一会重复产生数据的接口。

## 五、前端统一处理骨架

### 5.1 网页端（`web/`）

```
async function call(fn, action, payload) {
  try {
    const r = await callFn(fn, action, payload)   // 现有 callFn，不要重构
    if (r && r.ok) return r.data
    const code = (r && r.code) || 'ERR_UNKNOWN'
    if (code === 'ERR_NO_AUTH') { clearToken(); gotoLogin(); return null }
    if (code === 'ERR_EXPIRED' && fn === 'session') { refreshTicket(); return null }
    showToast(TEXT[code] || '操作失败，请重试')     // 只展示文案，不展示 error 原文
    return null
  } catch (e) {
    // 网络层：请求根本没发出去 / 超时
    showToast('网络异常，请检查网络后重试')
    return null
  }
}
```

### 5.2 小程序端（`miniprogram/services/request.ts`）

沿用现有 `call` / `callSafe` 返回 `{ ok, data, code, error }` 的结构**不要改**；在**页面层**按上表做文案映射。

> 现有 `request.ts` 已经把云函数返回包成了统一结构，**不要在 service 层弹 Toast** —— Toast 属于页面交互，由页面决定。

## 六、后端规范

| 编号 | 规范 |
|---|---|
| **E-B1** | 所有 action 用 `try/catch` 包住，catch 里返回 `{ ok:false, code:'ERR_UNKNOWN', error:'操作失败' }`，**不得把 `e.message` 直接抛给前端** |
| **E-B2** | 业务校验失败**用明确 code 返回**，不要抛异常 |
| **E-B3** | 每个异常分支 `console.error` 一条**带上下文**的日志：`[fn.action] code=xxx projectId=xxx openid=xxx` |
| **E-B4** | **禁止静默失败**：任何 `catch` 必须至少写一条日志 |
| **E-B5** | 云文件删除失败**不阻断主流程**（删项目、归档），但要记录 `failed` 列表 |
| **E-B6** | 权限校验失败统一返回 `ERR_NOT_FOUND`（**不透露资源是否存在**），避免资源枚举探测 |
| **E-B7** | 参数校验在进入业务逻辑**之前**完成 |

## 七、禁止的异常处理方式

| ❌ 禁止 | 原因 | ✅ 正确做法 |
|---|---|---|
| `catch(e) {}` 空吞 | 出问题无法排查 | 至少 `console.error` |
| 把 `e.message` 显示给用户 | 暴露内部实现，文案不可控 | 按 code 映射固定文案 |
| 用 Toast 展示技术错误码 | 用户看不懂 | 只展示文案 |
| 失败后无提示、页面卡在 loading | 用户不知道发生了什么 | 必须给终态（成功/失败/空） |
| 所有错误都提示「操作失败」 | 用户不知道下一步 | 给出具体动作 |
| 自动重试非幂等接口 | 会产生重复数据 | `project.create` 禁止自动重试 |
| 前端校验通过就跳过后端校验 | 可被绕过 | 后端必须独立校验（BR 规则中标注「后端」的） |

## 八、验收清单

- [ ] 断网时上传显示「已暂停」，网络恢复后可继续，已传的不重复传
- [ ] 断网时模特端顶部显示「网络异常」，恢复后自动补存
- [ ] 提交失败时**未锁定**，可重试；重复提交幂等
- [ ] 已提交的模特再次保存 → 收到 `ERR_LOCKED` 且前端引导「联系摄影师」
- [ ] 摄影师解锁后，模特端提示「已允许重新选择」且**原选择仍在**
- [ ] 超过张数上限时前后端都拦截
- [ ] 已归档项目模特端只读，`getPreview` 返回 `ERR_ARCHIVED`
- [ ] 登录二维码 5 分钟后置灰，点击可刷新
- [ ] token 过期时网页跳回登录页（不是报错）
- [ ] 剪贴板不可用时降级为「自动选中 + 手动复制」
- [ ] 所有页面在失败时都有明确终态，不存在永久 loading
- [ ] 前端界面上**找不到任何原始技术错误信息**
