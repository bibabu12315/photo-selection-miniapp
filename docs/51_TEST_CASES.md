# 51 · V2 测试用例

> **用例编号规则**：`TC-<模块>-<两位序号>`
> 模块：`AUTH` 身份会话 / `PROJ` 项目 / `UPLD` 上传画质 / `SEL` 模特选片 / `RSLT` 结果导出 / `NOTI` 订阅通知 / `PERM` 权限越权 / `EDGE` 异常边界
>
> **优先级**：`P0` 主链路与规则（不通过不能发布）· `P1` 重要分支 · `P2` 体验细节
>
> **前置条件缩写**：
> - **A 已开通** = 摄影师 A 的微信已在小程序引导页点过「我是摄影师」
> - **A 已登录** = A 在网页控制台扫码登录成功，sessionToken 有效
> - **P 存在** = 已用 A 建好一个测试项目 `TEST-xxx`

---

## 一、TC-AUTH · 身份与会话

### TC-AUTH-01 · 扫码登录主链路（P0）
**覆盖**：T-P0-2 / T-P1-1 · BR-101~105
**前置**：网页已部署静态托管；A 已开通
**步骤**
1. Chrome 打开控制台地址（不带 hash）
2. 把地址栏改成 `#/projects` 后回车
3. 回到登录页，用 A 的微信扫页面上的小程序码
4. 在小程序上确认
**预期**
- ① 显示小程序码，码下方有**倒计时**（5 分钟）
- ② 被重定向回登录页（未登录不可直达）
- ③ 小程序提示「已确认登录」
- ④ 网页 **2 秒内**自动进入项目列表，无需刷新

---

### TC-AUTH-02 · 未登录重定向（P0）
**覆盖**：T-P1-1 · BR-103
**前置**：浏览器 `localStorage` 已清空
**步骤**：直接访问 `#/projects` / `#/upload/xxx` / `#/result/xxx`
**预期**：三个地址全部重定向到登录页；**不出现任何项目数据**，控制台 Network 里对应请求返回 `ERR_NO_AUTH`

---

### TC-AUTH-03 · 小程序码过期（P1）
**覆盖**：T-P0-2 · BR-105
**步骤**：登录页生成码后**等待 5 分 30 秒**再扫
**预期**：小程序提示「二维码已失效」；网页码自动刷新为新的码；不产生任何 session 记录

---

### TC-AUTH-04 · 会话过期与退出（P1）
**覆盖**：T-P0-2 · BR-104
**步骤**
1. 已登录状态下点「退出登录」
2. 再访问 `#/projects`
3. （可选）在云开发控制台把该 session 记录的 `expireAt` 改成过去
**预期**
- ① 立即回到登录页，localStorage 中的 token 被清除
- ② 重定向到登录页
- ③ 下一次任意请求返回 `ERR_NO_AUTH`

---

### TC-AUTH-05 · 身份优先级（P0）
**覆盖**：T-P0-1 · BR-105
**步骤**：在云开发控制台云端测试，调用任一需要身份的 action，入参里**同时**伪造一个 `sessionToken`（指向摄影师 B）
**预期**：若调用方能拿到 OPENID，**以 OPENID 为准**，忽略入参里的 token。网页无法通过伪造 token 提权。

---

### TC-AUTH-06 · 模特不经过摄影师开通（P1）
**覆盖**：T-P0-1 · BR-102 / BR-108
**步骤**：模特 M1 的微信**从未**点过「我是摄影师」，直接扫邀请码进入项目
**预期**：M1 能正常选片；`model` 集合自动新增 M1 的记录；`admin` 集合**不新增** M1

---

### TC-AUTH-07 · sessionToken 不出现在 URL（P1）
**覆盖**：T-P1-1 · BR-104
**步骤**：登录后查看地址栏、查看任意请求的 URL 参数
**预期**：地址栏与请求 URL 中**均无 token**；token 只出现在请求 body 与 localStorage

---

### TC-AUTH-08 · 多端同时在线（P2）
**覆盖**：T-P0-2 · BR-104
**步骤**：A 在电脑 Chrome 登录，同时用另一个浏览器（或隐私窗口）再扫一次码
**预期**：两个会话**同时有效**，互不影响；退出其中一个不影响另一个

**预期**

- **云存储中该项目的 preview / thumbnail / 邀请二维码 全部被删**（这是 V2.2 修的，必须复验）
- 模特端再进入该项目 → 提示项目不存在
