# 10 · 页面规格

> **本文档是界面结构的唯一来源。** Coding AI 必须按此实现，不得自行增删区域、不得自行发明新页面。
> 样式必须沿用现有 CSS 变量（见 §0），不得引入 UI 框架、不得另起一套配色。
>
> 前置：`01_PRODUCT_SCOPE.md`（F-xx）、`03_USER_FLOW.md`（流程与状态）

## 零、通用约定

### 0.1 网页端（静态托管 · 单页 hash 路由）

| 项 | 规定 |
|---|---|
| 路由形式 | **hash 路由**：`#/login`、`#/projects`、`#/project/:id`、`#/project/:id/result` |
| 技术形态 | 单页应用，**不引入任何框架**（无 React/Vue）。原生 JS + 模板字符串渲染 |
| 文件组织 | 复用现有 `web/` 目录：`index.html` / `upload.js`（重构为 `app.js` + 各页模块）/ `style.css`（**扩展，不重写**） |
| 样式变量 | 沿用 `web/style.css:1-13` 已有变量；新增见下表 |

**网页端沿用变量**：`--fg #1a1a1a` / `--fg2 #4a4a4a` / `--muted #8a8a8a` / `--line #e8e8e8` / `--line2 #d8d8d8` / `--page #fafafa` / `--chip #f2f2f2` / `--ok #1d9e75` / `--ok-bg #e1f5ee` / `--err #e24b4a` / `--err-bg #fcebeb`

**新增变量（仅补充，不改已有）**：`--accent #185FA5`（主按钮/链接）、`--accent-bg #E6F0FB`、`--warn #BA7517`、`--warn-bg #FAEEDA`

> 网页端主色用蓝（后台管理系统观感），小程序端主色用绿（微信原生观感）。**两端不强行统一**。

### 0.2 小程序端

沿用 `miniprogram/app.wxss:1-16` 已有变量：`--bg` / `--page #f6f6f6` / `--fg` / `--fg2` / `--muted` / `--line` / `--line2` / `--chip` / `--green #1d9e75` / `--green-bg` / `--amber #ba7517` / `--amber-bg` / `--red #e24b4a` / `--red-bg`

### 0.3 状态四态（**每个页面必须有**）

| 状态 | 触发 | 表现 |
|---|---|---|
| **Loading** | 首次进入、刷新 | 骨架屏或居中「加载中…」；列表页用骨架卡片 ≥3 个 |
| **Empty** | 数据为空且非错误 | 居中插图位 + 一句话说明 **+ 明确的下一步按钮** |
| **Error** | 请求失败 | 居中错误文案 + 「重试」按钮；**不弹 alert** |
| **Success** | 操作成功 | Toast（2 秒自动消失）或状态就地变更 |

> **禁止**：用 `alert()` / 浏览器原生弹窗；用无下一步指引的空白页。

- **P-M·** 小程序摄影师端

## P-W1 · 扫码登录页

| 项 | 值 |
|---|---|
| **路由** | `#/login`（未登录时任意路由重定向到此） |
| **页面目的** | 让摄影师用微信扫码确认身份，进入自己的控制台 |
| **进入条件** | 无有效 sessionToken |
| **权限** | 无（公开页） |
| **对应功能** | F-01 / F-02 |

### 区域划分

| # | 区域 | 内容 | 说明 |
|---|---|---|---|
| 1 | 标题区 | 产品名 + 一句话「摄影线上选片 · 摄影师控制台」 | 沿用 `.brand` 样式 |
| 2 | 二维码区 | 小程序码图片（300×300），下方「请用微信扫描二维码登录」 | 5 分钟过期 |
| 3 | 状态区 | 三态之一：`等待扫码` / `已扫描，请在手机上确认` / `登录成功，正在进入…` | 轮询驱动 |
| 4 | 刷新区 | 过期后显示「二维码已过期，点击刷新」按钮 | 仅过期时出现 |
| 5 | 说明区（折叠） | 「首次扫码将自动为你开通摄影师身份」 | 消除陌生感 |

### 交互

| 操作 | 行为 |
|---|---|
| 页面加载 | 生成 loginToken → 请求小程序码 → 开始轮询（2s/次） |
| 点击刷新 | 重新生成 loginToken 与二维码，重置计时 |
| 登录成功 | 存 sessionToken 到 localStorage → 跳 `#/projects` |

### 状态

| 状态 | 表现 |
|---|---|
| Loading | 二维码区显示骨架方块 + 「正在生成二维码…」 |
| Error（生成失败） | 「二维码生成失败」+ 「重试」 |
| Error（网络断） | 状态区「网络异常，正在重试（第 N 次）」，退避重试 ≤3 次后显示重试按钮 |
| Success | 状态区变绿 + 「登录成功，正在进入…」→ 跳转 |

### 数据
- `POST /auth/qrcode` → `{ loginToken, qrUrl }`
- `POST /auth/poll` 入 `{ loginToken }` → `{ status: 'pending'|'confirmed', sessionToken? }`
- `POST /auth/confirm`（小程序端调用，非本页）

### 区域划分（自上而下）

| # | 区域 | 内容 | 备注 |
|---|---|---|---|
| 1 | 面包屑 | `项目列表 / {项目名}` | 可点击返回 |
| 2 | 项目头部 | 项目名（可就地改名）+ 状态标签 + 「余 M 天」+ 右侧操作：延期 / 归档 / 删除 | |
| 3 | **上传区** | 无照片时：大拖拽区「把照片或整个文件夹拖到这里」+「选择文件」按钮；有照片时：折叠为一行「已上传 N 张 · 继续添加」 | 见下方上传子流程 |
| 4 | **画质选择区** | 仅在选择文件后、上传前显示（F-06） | 见下方画质子流程 |
| 5 | 照片概览 | 缩略图网格（前 18 张）+「查看全部 N 张」 | 复用现有网格 |
| 6 | **模特进度区** | 每位模特一行：昵称 / 状态 / 已选张数 / 操作（`查看结果` `允许重选` `移除`） | |
| 7 | **邀请区** | 「+ 邀请模特」按钮 → 展开生成的小程序码 + 邀请链接 +「复制链接」/「下载二维码」 | F-07 |

### 上传子流程（区域 3-4）

```
步骤 A 选择文件
  - 拖拽文件夹 /「选择文件」多选
  - 显示待传列表：文件名、大小、总数；非图片文件标灰并标注「已跳过」
  - 若项目已有照片：顶部提示「已有 N 张，继续上传将追加；同名文件会覆盖」

步骤 B 画质预览（F-06）
  - 样张：默��第 1 张，提供「换一张」从已选文件中挑
  - 对比控件：左右滑块（默认 标准 vs 高清），下拉可切换对比对象
  - 查看模式：适应窗口 / 100% 原始像素（可切换，默认适应）
  - 每档标注：长边像素 · quality · 单张预估体积
  - 汇总行：「这批 N 张 ≈ XXX MB」（标注「预估」）
  - 纯浏览器本地生成，不上网

步骤 C 上传
  - 按钮「开始上传（N 张）」
  - 进度：总数进度条 + 当前文件名 + 已用时间
  - 并发 3，失败自动重试 2 次

步骤 D 完成
  - 成功页：绿色勾 + 「成功上传 N 张」+ 失败 M 张（有则列出+重试按钮）+「本次占用 XXX MB」
  - 主按钮：「去邀请模特」（滚动到区域 7）；次按钮「继续添加」
```

### 状态

| 状态 | 表现 |
|---|---|
| Loading | 头部骨架 + 内容区骨架 |
| Empty（无照片） | 大拖拽区（区域 3 的空态即主引导） |
| Empty（无模特） | 「还没有邀请模特」+「+ 邀请模特」按钮 |
| Error（项目不存在） | 「项目不存在或已被删除」+「返回列表」 |
| Error（无权限） | 「无权访问该项目」+「返回列表」 |
| Error（上传失败） | 步骤 D 的失败列表 |

### 数据
- `POST /project/get` 入 `{ projectId }`
- `POST /photo/register`（现有 `photo` 云函数，复用）
- `POST /project/invite` 入 `{ projectId }` → `{ qrUrl, link }`
- `POST /project/extend` / `archive` / `remove`（现有 action 复用）
