# 11 · 交互规格

> **本文档定义所有可交互行为的规则、时机与反馈。**
> Coding AI 实现时不得自行改变交互语义（尤其是选中、提交、锁定、解锁四处）。
>
> 前置：`01_PRODUCT_SCOPE.md`、`03_USER_FLOW.md`、`10_PAGE_SPEC.md`

---

## 一、反馈层级（什么时候用哪一种）

| 层级 | 用于 | 时长 | 是否阻断操作 |
|---|---|---|---|
| **内联提示** | 字段级错误、额度提示、未保存提示 | 常驻直到解决 | 否 |
| **Toast** | 操作成功的轻反馈（复制成功、已保存） | 2 秒自动消失 | 否 |
| **状态就地变更** | 提交成功、解锁成功等状态类结果 | 常驻（页面状态变化） | 否 |
| **确认弹窗** | 不可逆或影响他人的操作 | 需用户点击 | **是** |
| **页面级状态** | 加载/空/错误/无权限/已过期 | 常驻 | 是 |

### 确认弹窗的准入门槛（**只在这 5 处使用**）

| # | 场景 | 文案 |
|---|---|---|
| 1 | 模特提交选片 | 「已选 N 张，提交后将不能自行修改。确认提交吗？」 |
| 2 | 摄影师解锁重选 | 「她将可以在已选的 N 张基础上继续调整（可加可减）。确定吗？」 |
| 3 | 摄影师删除项目 | 「删除后照片与选片结果将永久消失，无法恢复。确定删除吗？」 |
| 4 | 摄影师归档项目 | 「归档后将删除大图预览、释放空间，仍保留缩略图与文件名。确定吗？」 |
| 5 | 退出登录 | 「退出后需要重新扫码登录。确定吗？」 |

> **其余任何操作一律不得加确认弹窗。** 尤其是：勾选照片、自动保存、刷新列表、切换 tab。

### Toast 文案模板

| 场景 | 文案 |
|---|---|
| 复制成功 | 「已复制 N 个文件名」 |
| 自动保存成功 | 「已保存」（**静默为佳，见 §4.3**） |
| 达上限 | 「最多可选 M 张」 |
| 解锁成功 | 「已允许她重新选择」 |
| 邀请链接复制 | 「链接已复制，发给模特即可」 |
| 网络失败 | 「网络异常，请检查后重试」 |
| 额度不足 | 「空间不足，剩余可传 N 张」 |

## 二、通用交互规则

### 2.1 点击

| 规则 | 说明 |
|---|---|
| 点击区域 ≥ 44×44px | 小程序端所有可点元素；网页端 ≥ 32×32px |
| **禁止双击穿透** | 提交、删除等按钮点击后立即置 `disabled`，防止连点 |
| 长按 | 模特端**不做**长按菜单（避免与手势冲突） |
| 点击反馈 | 网页端 `:active` 变色；小程序端用 `hover-class` |

### 2.2 返回

| 场景 | 行为 |
|---|---|
| 小程序内返回 | 系统返回键 / 左上角返回，按页面栈正常回退 |
| 大图返回 | 返回到网格，并**滚动到刚才看的那一张**（不得回到顶部） |
| 网页端返回 | 浏览器后退需与 hash 路由一致（监听 `hashchange`） |
| 模特提交后返回 | 再次进入仍是 locked 只读态，**不会**回到可编辑 |

### 2.3 禁用态

| 元素 | 禁用条件 | 表现 |
|---|---|---|
| 提交按钮 | 已选 0 张 / 正在提交中 / 已锁定 | 灰底 + 不可点 |
| 勾选徽章 | 已达上限且当前未选 / 已锁定 | 不可点（**不隐藏**，保持可见以显示状态） |
| 上传按钮 | 未选文件 / 正在上传中 | 灰底 |
| 邀请按钮 | 模特数已达 5 | 灰底 + 提示「最多 5 位模特」 |

> 禁用必须**视觉可见**（灰底或降透明度），不得只是静默不可点。

## 三、图片浏览

### 3.1 网格

| 项 | 规则 |
|---|---|
| 布局 | 小程序端沿用现有 `.grid`（3 列）；网页端 4~6 列自适应 |
| 图片比例 | `mode="aspectFill"` 正方形裁切（现有行为，保持） |
| 间距 | 沿用现有值，**不调整** |
| 分页 | 小程序端 18 张/页滚动加载（现有）；网页端 60 张/页 |

### 3.2 淡入（F-22）

```
<image> 加载完成（bindload） → 加 class .loaded
.loaded { opacity: 1; transition: opacity .2s ease }
初始 .thumb { opacity: 0 }
```

- **必须**加，消除 4G 下图片逐张"跳入"
- 缓存命中的图片应**立即显示**（无淡入），避免闪烁：判断 `bindload` 是否在 100ms 内触发

### 3.3 大图浏览（不得重写）

| 手势 | 行为 |
|---|---|
| 左右滑 | 切换上一张 / 下一张 |
| 双指 | 缩放（1x ~ 3x） |
| 双击 | 在 1x 与 2x 间切换 |
| 放大后贴边再滑 | 切图（当前已实现） |
| 轻点（未放大时） | 选中 / 取消（当前实现为「轻点选片」） |
| 单击空白 / 返回键 | 退出大图 |

**实现约束**：手势逻辑在 `gest.wxs` 渲染层处理，**不得迁移到逻辑层**（会卡顿）。V2 只允许加 `bindload` 淡入与加载失败占位，不得改动手势判定逻辑。

**加载失败**：显示占位图 + 「点击重试」，重试 1 次；仍失败保持占位，不阻塞切图。

## 四、选择交互（最核心，语义不得改）

### 4.1 状态机

```
未选择 ──点徽章/轻点──▶ 已选择 ──再点──▶ 未选择
```

| 状态 | 视觉 |
|---|---|
| 未选择 | 空心圆圈徽章（半透明白底） |
| 已选择 | 实心绿底 + ✓ |
| 已达上限时的未选项 | 徽章降透明度 + 不可点 |

### 4.2 上限规则

| 规则 | 说明 |
|---|---|
| 张数上限来源 | `project.limit`（套餐张数），创建项目时设定 |
| 达上限时 | 前端禁止再选 + Toast「最多可选 M 张」 |
| **后端必须二次校验** | `saveSelection` 若 `photoIds.length > limit` 直接拒绝 |
| 无上限设置时 | `limit` 为空表示不限，此时不显示「/ M」 |

### 4.3 自动保存

| 规则 | 值 |
|---|---|
| 触发 | 选择变更后 **2 秒防抖** |
| 成功 | **静默**（不弹 Toast），仅底栏状态保持 |
| 失败 | 顶部出现内联条「未保存，正在重试」→ 退避重试（1s / 3s / 9s） |
| 重试仍失败 | 保持「未保存」条 + 提示「请检查网络」 |
| 页面离开时 | 若仍有未保存变更，**立即强制保存一次**（不等防抖） |
| 已锁定 | **不接受任何保存**（后端拒绝，R-1��� |

### 4.4 提交

```
点「提交选片」
  → 确认弹窗（§1 场景 1）
  → 提交中：按钮置 disabled，显示「提交中…」
  → 成功：整页切换为 locked 只读态（不是 Toast）
  → 失败：Toast + 按钮恢复可点，选择保留
```

| 规则 | 说明 |
|---|---|
| 幂等 | 已 `locked` 时重复提交直接返回成功，**不报错** |
| 提交数 0 | 前端拦截，不弹确认 |
| **locked 后** | 前端无修改入口；后端 `saveSelection` 拒绝写入（R-1） |

## 五、上传交互（网页端）

### 5.1 选择文件

| 规则 | 说明 |
|---|---|
| 支持 | 多选文件 + **整个文件夹拖拽**（保留 `relPath` 用于排序） |
| 支持格式 | `.jpg` `.jpeg` `.png` `.webp`；其他格式在列表中标灰并计入「已跳过」 |
| 列表 | 显示文件名 + 大小 + 总数；超过 500 张时提示「本次上传较多，请保持页面打开」 |
| 去重 | 与项目已有照片同名的，标黄提示「将覆盖 N 张」 |

### 5.2 画质预览（F-06）

| 交互 | 规则 |
|---|---|
| 样张 | 默认已选文件的第 1 张；「换一张」从已选文件中另挑 |
| 对比 | 左右滑块拖动，左半显示 A 档、右半显示 B 档；默认 A=标准、B=高清 |
| 切换对比对象 | 两个下拉框，可选四档任意组合 |
| **100% 查看** | 必须提供「适应窗口 / 100%」切换；100% 时显示局部原尺寸像素 |
| 标注 | 每档下方显示：`长边 1600 · q75 · ≈0.25 MB/张` |
| 汇总 | 「这批 N 张 ≈ XXX MB」+ 小字「预估，实际以云端为准」 |
| **实现方式** | 浏览器本地 `createImageBitmap` + `OffscreenCanvas` + `toBlob`。**不上传、不联网、不消耗云资源** |
| 默认档 | 标准（1600 / 0.75） |

### 5.3 上传过程

| 规则 | 说明 |
|---|---|
| 并发 | 3（沿用现有） |
| 进度 | 总进度条 + 当前文件名 + 已用时间；**不显示单张百分比** |
| 单张失败 | 自动重试 2 次；仍失败标红，进入失败列表 |
| 网络断开 | 暂停并显示「已暂停，等待网络恢复」；恢复后**自动继续** |
| 页面关闭/刷新 | 已成功的不再重复传（按文件名比对）；重新进入提示「上次有 N 张未完成」 |
| 禁止 | **不做**断点续传（单张续传），失败即整张重传 |

### 5.4 完成

| 元素 | 内容 |
|---|---|
| 主提示 | 绿色勾 + 「成功上传 N 张」 |
| 失败项 | 若有：红字「M 张失败」+ 展开列表 + 「重试失败的」按钮 |
| 占用 | 「本次占用 XXX MB」 |
| 主按钮 | 「去邀请模特」 |
| 次按钮 | 「继续添加」 |

## 六、导出交互（F-09）

| 规则 | 说明 |
|---|---|
| 排序 | **按文件名升序**（V1 既有约定，不得改） |
| 复制 | 一行一个纯文件名（不含路径、不含扩展名以外的字符） |
| 复制失败降级 | 自动选中文件名列表区域的文本 + 提示「请手动复制（Ctrl+C）」 |
| CSV 列名 | `序号,文件名,模特备注名` |
| CSV 文件名 | `{项目名}-{模特名}-选片清单.csv` |
| 编码 | UTF-8 **带 BOM**（保证 Excel 打开中文不乱码） |
| 「全部合并」tab | 多模特结果去重合并后导出（同一张被多人选中只出现一次） |

## 七、扫码登录交互（F-01）

| 阶段 | 网页显示 | 小程序显示 |
|---|---|---|
| 生成 | 二维码 + 「请用微信扫描二维码登录」 | — |
| 已扫描 | 「已扫描，请在手机上确认」 | 确认页：「登录电脑端控制台？」+ 摄影师昵称 + 「确认登录」按钮 |
| 已确认 | 「登录成功，正在进入…」→ 跳转 | 「登录成功」→ 自动关闭 |
| 过期 | 二维码变灰 + 「已过期，点击刷新」 | — |

| 规则 | 值 |
|---|---|
| 二维码有效期 | 5 分钟 |
| 轮询间隔 | 2 秒 |
| 轮询超时 | 5 分钟，超时后停止并提示��新 |
| 网络重试 | 指数退避，最多 3 次 |
| sessionToken 有效期 | 30 天，存 `localStorage` |
| 首次扫码 | 小程序端顺带隐式建档为摄影师，确认页提示「将为你开通摄影师身份」 |

## 八、通知交互（F-14）

| 规则 | 说明 |
|---|---|
| 授权时机 | 摄影师在**发邀请**这一步勾选「选片完成通知我」 |
| 授权性质 | 微信订阅消息为**一次授权一次推送**，每位模特提交消耗一次 |
| 推送内容 | 「{模特名} 完成了《{项目名}》的选片，共 N 张」 |
| 点击通知 | 直达小程序项目详情页 |
| 未订阅 | 静默不推，**不做**任何替代通知 |
| 禁止 | 不得在无关页面反复弹授权（体验差且审核风险） |

## 九、动效规范

| 场景 | 时长 | 曲线 |
|---|---|---|
| 图片淡入 | 200ms | ease |
| Toast 出现/消失 | 150ms / 200ms | ease-out |
| 弹窗出现 | 200ms | ease-out |
| 页面切换（网页端） | 150ms 淡入 | ease |
| 按钮 `:active` | 瞬时 | — |

> 小程序端**不做**页面转场自定义动画（用系统默认）。

## 十、禁止事项（交互层面）

| # | 禁止 |
|---|---|
| 1 | 用浏览器原生 `alert` / `confirm` / `prompt` |
| 2 | 在锁定态保留任何自助修改入口（按钮、长按、双击都算） |
| 3 | 自动保存成功弹 Toast（应静默） |
| 4 | 给非不可逆操作加确认弹窗 |
| 5 | 改动 `gest.wxs` 的手势判定逻辑 |
| 6 | 引入 UI 组件库（Vant / Element / Ant 等） |
| 7 | 引入前端框架（React / Vue / 小程序框架） |
| 8 | 静默失败——任何失败必须有可见反馈 |
| 9 | 无限重试（所有重试必须有次数上限） |
