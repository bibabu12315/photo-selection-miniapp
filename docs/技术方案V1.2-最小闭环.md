# 摄影线上选片小程序 · V1.2 最小闭环

> 本文取代《技术方案修订-V1.1》中与之冲突的部分。
> 修订日期：2026-10-01
> 核心变化：**砍掉手机端上传、砍掉精修交付**，V1.0 只做「上传 → 选片 → 看结果」。

---

## 一、V1.0 的最终定义

> 让模特能在手机上看到这次拍摄的每一张照片，选出她喜欢的，把结果告诉摄影师；摄影师拿到文件名，回 Lightroom 精修，微信单独交付。

精修交付不进小程序。V1.0 的终点是**摄影师看到选片结果**。

## 三、V1.0 最终闭环

```
拍摄（ARW + JPG 写入 SD 卡）
   ↓
读卡器插电脑，打开上传页，输入 6 位上传码
   ↓
拖入 DCIM 文件夹（按文件夹勾选今天这批）
   ↓
浏览器压缩 + 加水印 → 上传 preview + thumbnail
   ↓
小程序生成小程序码 / 分享卡片 → 发给模特
   ↓
模特扫码浏览 300 张缩略图，点大图看 preview
   ↓
点♡选片 → 提交（锁定）
   ↓
摄影师在小程序或电脑端查看选片结果
   ↓
   ├── 缩略图网格
   ├── 文件名清单（DSC00123.JPG ...）
   └── 一键复制全部文件名
   ↓
回 Lightroom 按文件名精修 ARW
   ↓
微信发送精修图交付     ← 不在小程序内
```

## 四、摄影师身份方案：openid 白名单

### 4.1 评估结论

- **不需要可见的登录界面。** 小程序内 `wx.login` 静默获取 openid，无授权弹窗、无按钮、无 UI，云函数里三行代码。
- **不需要获取昵称头像。** 那需要 `<button open-type="chooseAvatar">` 用户主动授权，V1.0 无意义。
- **同一微信账号在同一小程序内的 openid 永久固定**，换手机、重装微信都不变。

### 4.2 落地方式

```
用户打开小程序
   ↓
app.ts: wx.login → 云函数换 openid → 本地缓存
   ↓
是否带 scene token？
   ├── 是 → 进入模特端（校验 token 有效性）
   └── 否 → 比对 openid
          ├── 命中管理员 → 摄影师端
          └── 未命中   → 显示「请用摄影师分享的二维码进入」
```

管理员绑定**不能**用「第一个打开的人自动绑定」——若模特先于摄影师打开，她会被绑成管理员并看到所有项目。

- **方案 A（推荐）**：云函数环境变量设 `ADMIN_BIND_KEY`，首次打开需输入该口令才绑定管理员。
- **方案 B**：环境变量 `ADMIN_OPENID` 硬编码（需先从云函数日志取出自己的 openid 再回填）。

管理员一经绑定不允许再次绑定，重置只能到 CloudBase 控制台手动改库。

> 访问控制完整设计（四道锁、一码一人、能防住与防不住的边界）见 `docs/安全与访问控制.md`。

## 五、预览规格定稿

电脑端上传页提供三档，滑杆在 HTML 里实现，1% 精度无难度。

| 档位 | 长边 | JPEG 质量 | 单张体积 | 说明 |
|---|---|---|---|---|
| 标准（默认） | 2048 | 82 | 400–700 KB | 手机屏 2x 已够，加载快 |
| 高清 | 2880 | 90 | 0.9–1.5 MB | 模特想放大看细节时用，流量较大 |
| 自定义 | 1200–4096 | 40–95 | — | 两个滑杆，实时预览首张效果 |

- **thumbnail 固定**：长边 480、质量 75、约 30–50 KB，不随档位变化。
- 原方案 2400–4000 偏大：手机上预览不需要，且 300 张的高清档全浏览会吃掉几百 MB 流量。
- **V1.1 候选**：preview 输出 WebP，同质量下体积再降 25–35%。V1.0 用 JPEG 保证零兼容风险。

## 六、选片结果页设计

摄影师的核心诉求是「拿到文件名去 LR 里找 RAW」，所以这一页的设计原则是**文件名优先**。

- **默认列表视图**：左侧 80px 缩略图，右侧 `序号 + DSC00123.JPG`。摄影师可以按顺序在 LR 里逐个定位。
- **可切网格视图**：纯缩略图，快速扫一眼。
- **一键复制全部文件名**：复制到剪贴板，可粘贴到任意地方。
- **排序**：固定按文件名升序（`sortOrder`），与 LR 默认排序一致，保证两端顺序对齐。

> 关键点：`sortOrder` 必须按文件名排序，否则小程序里的第 37 张和 LR 里的第 37 张对不上。

### project

uploadCode       6 位一次性上传码

```

### photo

```
_id, projectId
originalFilename "DSC00123.JPG"    ← 选片结果的核心输出

> `folderPath` **不入库**。文件夹分组只在电脑上传页的本地 UI 中存在，用于勾选范围，选片结果里不需要。

### selection（项目级单文档）

```
_id, projectId
clientOpenid
photoIds      [ ... ]
locked        false
submittedAt, updatedAt
```

### admin

```
_id, openid, boundAt
```

## 十、Phase 划分（重排）

| Phase | 内容 | 验收 |
|---|---|---|
| 0 | 环境 + 工程初始化 | 小程序能跑、能调云函数、能读写库；上传页能打开并传一张图 |
| 1 | 项目管理 | 建项目 → 刷新 → 还在；生成上传码 |
| 2 | **电脑端上传 + 图片派生** | 拖 100 张 JPG → 自动生成 preview/thumbnail → 小程序能看到 |
| 3 | 分享入口 | 小程序码 + 分享卡片，另一台手机能进正确项目 |
| 4 | 模特选片 | 选 10 张 → 提交 → 摄影师端显示 10 张 |
| 5 | 选片结果 | 缩略图 + 文件名 + 一键复制 |
| 6 | 稳定性 | 300 张、弱网、重复提交、退出重进 |

Phase 2 是全程最难的一环，压缩、队列、失败重试都在这里，建议留足时间。
