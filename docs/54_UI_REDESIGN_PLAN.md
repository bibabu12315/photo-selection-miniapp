## 2. 开工前必须确认的 4 件事

### D-1 【已拍板 2026-10-05】小程序端不加「新建项目」按钮 → 遵守规则

- **决定**：**不加**。以 `BR-206` / `BR-1204` 为准，小程序端保留**引导**而非入口。
- **规则依据**：`BR-206`「项目只能在网页端新建，小程序端入口已移除」；`BR-1204`「小程序端必须移除：新建项目、上传照片、选择画质、导出清单」。
- **所以要做的是**：把「完整管理请在电脑上操作 · 复制控制台地址」做成**显眼的顶部引导条**（现状 `home/index.wxml:3-6` 只是普通提示条），让摄影师一眼知道「要建项目 → 复制链接去电脑」。
- **连带**：`spec.html` 第二章第 2 屏画的「新建项目」按钮**作废**，以本文件为准。设计稿后续若再画，按引导条处理。

### D-2 【必做 · 最高优先级】照片墙缺「按项目列出全部照片」的接口

- **状态**：**已拍板必做**，不是可选项。规格见 **`docs/55_PHOTO_LIST_API_SPEC.md`**（入参 / 出参 / 鉴权 / 分页 / 验收清单全在里面）。
- **要新增**：`photo.list`（放在 `photo` 云函数，摄影师视角，分页 18，`have` 缓存机制，返回 `width/height/filename/selectedBy[]/models[]`）。
- **现状为什么不够**：`photo` 云函数只有上传链路三个 action；`project.get` 只返回 3 张封面；`selection.getPhotos` 是**模特视角**（`guardModel` 校验）；`selection.getProjectResults` 只有 `filenames`，没有 `_id/宽高/缩略图`，画不出墙。
- **依赖它的任务**：A-4（网页端照片墙）、B-4（摄影师端照片墙）。**接口没好之前这两处只能先画壳**（用 `coverThumbs` 验证视觉）。
- **注意**：`project.get` **不要**塞照片列表进去（大项目会撑爆）。

### D-3 【需后端 / 可降级】照片墙的「已选 / 未选」筛选

- 设计稿要求 Tab：全部 / 已选 / 未选，且「已选」下按模特出 chips。
- 需要每张照片带 **选中人信息**（多模特各自独立，`BR-405`）。
- 降级方案（不想动后端时）：摄影师端照片墙先只做「全部 / 未选」，**已选部分直接跳已有的 `selection-result` 页面**（该页已按模特 tab 展示已选，见 B-4）。

### D-4 【需确认】模特历史回看是否已在代码里生效

- **规则已写**：`BR-108`「模特身份 = openid，首次扫邀请码隐式建档，之后直接打开小程序即可看到全部历史项目」、`BR-404` 同义。
- **要确认**：`model-home` 的列表接口是否按 openid 查全部项目（含无新拍摄计划的旧项目）。若已实现，设计稿里「历史回看」只需改 UI 文案（补「剩 X 天」提醒）；未实现则属于功能缺失，不属于本轮 UI 范围，单独列任务。
- **UI 上必须说清**：回看的是**云端预览图**（`BR-306` 原图不上云），回看窗口 = 存续期（默认 30 天，可续期 +30）。

### 附带确认（不算冲突，改之前瞄一眼）

- **提交即锁定**：设计稿 V1.2 的「模特端取消自行改选」与 `BR-601/602/605` **完全一致**，不用改规则。但 `BR-602` 要求删除 `client-select` 的「继续调整」按钮 —— 现 `client-select/index.wxml:24-26` 是 `resubmitHint` 提示条（不是按钮），且只在**摄影师解锁后**出现，属于合规场景；`BR-702` 要求的解锁文案已在 `selection-result/index.ts:132` 改正。这两处**保持现状，不要动**。
- **模特复制全部文件名**：`selection-result/index.wxml:42` 已有「复制全部文件名」；注意 `BR-802`「导出清单是网页端独有」，小程序端**只能复制，不能导出文件**。

## 6. 瀑布流统一实现规范（三端同一规则）

**数据源**：照片记录已含 `width` / `height`（`21_DATABASE.md` 第 118 行，预览图尺寸），直接用来算比例。

| 端 | 实现方式 | 说明 |
|---|---|---|
| **网页端** | CSS `columns: 4`（<1100px → 3 列），`column-gap: 4~8px`，子项 `break-inside: avoid` | 简单可靠；`mockup.html` 的 `.masonry` 就是这么写的 |
| **小程序端** | **JS 分列**，不要依赖 WXSS `column-count` | 渲染器差异有风险。做法：维护两列累计高度数组，每张照片按「当前较矮的一列」投放，`height = 列宽 × photo.height / photo.width` |

**通用约束**：
- 缩略图用 `thumbFileID` 换 tempFileURL，**端上缓存 20 小时**（`BR-505`，不得每次渲染重取）；
- 分页 **18 张**（`PHOTO_PAGE_SIZE`），滚动加载，保留「加载失败，点此重试」；
- 图片 `mode="aspectFill"` + `lazy-load`，`bindload` 淡入（`BR-507`）；
- 列间距 4~8px，不要 0（零间距会让照片粘在一起，视觉更乱）；
- 已选照片用绿框 + 对勾（`#4CAF7D`），与模特端一致。

## 9. 阶段 E · 体验增强清单（PM 视角补充）
