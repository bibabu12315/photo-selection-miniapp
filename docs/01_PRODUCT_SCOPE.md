## 一、产品定位

### 1.1 一句话定位

> **一个面向独立摄影师 / 摄影爱好者的轻量级线上选片工具：摄影师在电脑网页上传，模特在微信小程序里选，选完摄影师拿回文件名清单，回到自己的修图工作流。**

### 1.2 与竞品（绚篇）的根本差异

| | 绚篇 | 本项目 |
|---|---|---|
| 商业模型 | 会员订阅 + **交易抽佣 2%**（加片/售图/打赏） | 无商业模型（自用工具，未来可能开源） |
| 服务终点 | **交付给客户**（精修、相册、二销） | **回到摄影师自己的工作流**（输出文件名清单） |
| 目标客户 | 影楼 / 工作室 | 用 Lightroom 自己修图的独立摄影师、爱好者 |
| 多端 | 网页 + 桌面客户端 + 小程序 | **网页 + 小程序**（明确不做原生 App / 桌面客户端） |

**一句话概括差异**：绚篇解决"怎么把照片卖出去并交付"，本项目解决"怎么知道客户选了哪几张"。

> 这条差异是产品边界的判断依据。**凡是把产品推向"交付/售卖"方向的功能，一律不做。**

## 二、核心用户

### 2.1 摄影师（主用户）

| 项 | 定义 |
|---|---|
| 身份 | 微信 openid 隐式建档（首次扫码登录即建档） |
| 主要设备 | **电脑（网页控制台）为主**，手机（小程序）为辅 |
| 使用频率 | 爱好者：月度 1~2 单；高频：月度 10~20 单 |
| 数据归属 | 一个项目**有且仅有一个**摄影师（负责人），`project.ownerOpenid` |
| 核心诉求 | 快速把照片传上去 → 发个码给模特 → 拿回文件名清单 |

### 2.2 模特 / 客户（次用户）

| 项 | 定义 |
|---|---|
| 身份 | 微信 openid 隐式建档，**零注册、零登录**（首次点邀请链接即建档） |
| 设备 | 手机（微信小程序） |
| 数量 | 同一项目最多 **5 位模特，各自独立选片、互不可见** |
| 核心诉求 | 打开就能看、看清楚、勾完提交 |

### 2.3 明确不是本产品用户

- 影楼 / 工作室的**团队账号**、子账号、多角色协作（R-5）
- 购买照片的终端消费者
- 需要收款、开票、对账的商业主体

## 三、核心场景

| # | 场景 | 描述 |
|---|---|---|
| S-1 | 拍摄后交付选片 | 摄影师拍完回家，电脑上把 JPG 预览图批量传上去，微信发二维码给模特，模特当晚选完提交，摄影师第二天看到清单开始修图 |
| S-2 | 一次拍摄多位模特 | 同一批照片给 2~5 位模特各发一个码，各自选自己的，摄影师分别看结果 |
| S-3 | 模特改主意 | 模特提交后想改 → 摄影师解锁 → 模特在原选择基础上增删 → 再次提交 |
| S-4 | 咖啡馆当场选（保留） | 现场用手机微信扫码即可选，不必等回家 |
| S-5 | 项目结束归档 | 项目超过存续期后自动归档（删 preview、留 thumb 与文件名），摄影师仍可看到历史项目 |

## 四、核心任务（按用户目标组织，不是按页面）

### 4.1 摄影师

| # | 任务 | 成功标准 |
|---|---|---|
| T-P1 | 登录电脑端控制台 | 打开网页 → 微信扫一下 → 进入自己的项目列表。不需要输入任何码 |
| T-P2 | 创建一次拍摄项目 | 填项目名 + 套餐张数上限 → 生成成功 → 立即可上传 |
| T-P3 | 上传照片 | 拖入整个文件夹 → 选画质（有预览对比）→ 传完看到明确完成提示 |
| T-P4 | 邀请模特 | 生成一个二维码 / 链接 → 微信转发给模特 → 模特点开即进入 |
| T-P5 | 知道模特选到哪了 | 项目列表上直接看到每位模特的进度（未开始 / 选片中 / 已提交）与已选张数 |
| T-P6 | 拿到最终清单 | 一键复制全部文件名 / 导出 CSV，按文件名升序 |
| T-P7 | 让模特改一次 | 解锁 → 模特改 → 重新提交 → 结果更新 |

### 4.2 模特

| # | 任务 | 成功标准 |
|---|---|---|
| T-M1 | 进入项目 | 点链接或扫码 → 直接看到照片，无需注册 |
| T-M2 | 快速浏览 | 缩略图网格流畅滚动，不卡 |
| T-M3 | 认真看 | 点开大图能放大、能左右滑、看得清 |
| T-M4 | 选择 | 勾选/取消状态一目了然，有已选计数 |
| T-M5 | 提交 | 提交后明确告知"已提交，如需修改请联系摄影师" |

## 六、V2 必须做（功能清单）

> 编号 `F-xx` 为后续任务拆分、测试用例、验收清单的统一引用编号。

### 6.1 网页控制台（新增 · 本轮主体）

| 编号 | 功能 | 说明 | 依赖 |
|---|---|---|---|
| **F-01** | 扫码登录 | 网页生成小程序码（scene=loginToken）→ 摄影师扫码 → 网页轮询取得会话 → localStorage 保持登录 | 云开发 HTTP 访问服务 |
| **F-02** | 会话保持与登出 | sessionToken 有效期 30 天，存 localStorage；提供「退出登录」 | F-01 |
| **F-03** | 项目列表 | 表格/卡片展示：项目名、状态标签、照片数、模特数及各自进度、剩余存续天数、占用容量 | F-01 |
| **F-04** | 新建项目 | 项目名 + 套餐张数上限（模特最多可选 N 张） | F-01 |
| **F-05** | 批量上传 | 拖拽文件夹/多文件，并发 3、失败重试、进度条、完成提示（**移植现有 `web/upload.js`**） | F-01 |
| **F-06** | 画质预览对比 | 选完文件后，用真实样张本地生成四档，左右滑块对比 + 100% 放大 + 显示「这批 N 张 ≈ XXX MB」 | F-05 |
| **F-07** | 邀请二维码 | 项目详情页生成模特邀请小程序码，可下载 PNG，可复制邀请链接 | F-01 |
| **F-08** | 选片结果查看 | 按项目 → 按模特查看：已选张数、缩略图网格、文件名列表 | F-01 |
| **F-09** | 导出文件名清单 | 一键复制（按文件名升序）/ 导出 CSV | F-08 |
| **F-10** | 项目操作 | 延期、归档、解锁模特重选、删除（删除连云存储一起删） | F-01 |

## 十、V2 交付后的形态（验收时的样子）

1. 摄影师打开网页控制台地址 → 出现一个小程序码
2. 微信扫一下 → 网页自动进入，看到自己的项目列表
3. 点「新建项目」→ 填名字和张数上限 → 进入上传
4. 把相机文件夹整个拖进去 → 画质预览滑块看一眼差别 → 开始上传 → 完成提示
5. 点「邀请模特」→ 出现二维码，下载或直接微信转发
6. 模特扫码 → 微信内浏览 → 勾选 → 提交 → 看到"已提交"
7. 摄影师收到订阅消息 → 打开控制台 → 看到结果 → 一键复制文件名 → 粘到 Lightroom 里筛

> 这条链路走通，V2 即完成。链路之外的任何东西，都不在范围内。
