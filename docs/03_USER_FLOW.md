# 03 · 用户流程与状态流转

> **本文档定义所有用户路径的正常流程、分支与异常。**
> Coding AI 实现时，凡本文档已定义的分支，必须实现；未定义的分支出现时，按 `32_ERROR_HANDLING.md` 的兜底规则处理，不得自行发挥。
>
> 前置：`01_PRODUCT_SCOPE.md`（功能编号 F-xx 引用自此）

## 零、全局状态定义（先统一口径）

### 0.1 项目状态（`project.status`，存储值仅 5 个）

| 状态 | 含义 | 进入条件 | 退出条件 |
|---|---|---|---|
| `DRAFT` | 已创建、尚未上传任何照片 | 新建项目 | 第一张照片登记成功 → `UPLOADING` |
| `UPLOADING` | 可上传 / 可继续上传 | 照片登记；或归档项目被续期恢复 | 模特首次进入 → `SELECTING` |
| `SELECTING` | 已有模特进入并可能正在选 | 模特首次访问项目 | 所有模特提交 → `SELECTION_SUBMITTED` |
| `SELECTION_SUBMITTED` | 至少一位模特已提交 | 模特提交 | 摄影师解锁 → 回 `SELECTING` |
| `ARCHIVED` | 已归档（preview 已删，保留 thumb 与文件名） | 超过存续期惰性触发；或摄影师手动归档 | 摄影师续期 → 回 `UPLOADING` |

**派生态（不落库，页面现算）**：
- **已过期**：`expireAt < now`。此时模特端禁止选片，摄影师端提示"已过期，可续期"
- **归档宽限中**：`expireAt < now` 且未超过宽限期（7 天），尚未真正归档

> **禁止**新增 `COMPLETED`、`EXPIRED`、`CLOSED` 等存储状态（R-3）。

### 0.2 模特选片状态（`selection`，按 (projectId, modelId) 双人键）

```
未开始  ──模特首次打开──▶  选片中  ──提交──▶  已提交（锁定）
                            ▲                    │
                            └──── 摄影师解锁 ──────┘
```

| 状态 | 模特能做什么 | 数据写入时机 |
|---|---|---|
| 未开始 | 浏览、选择 | 选择变更后 2 秒防抖自动保存 |
| 选片中 | 浏览、选择、取消选择 | 同上 |
| 已提交（锁定） | **只能看，不能改**（R-1） | 提交时写入 `locked=true, submittedAt` |
| 已解锁 | 浏览、在原选择基础上增删 | 解锁后重新进入自动保存 |

### 0.3 上传任务状态（web 端本地，不落库）

```
待上传 → 上传中 → 上传成功
            └──→ 上传失败 → 等待重试 → 上传中
```

## 一、摄影师完整流程

### 1.1 首次登录（F-01）

```
打开控制台网页
  │
  ├─ localStorage 有有效 sessionToken？
  │     ├─ 是 → 直接进项目列表
  │     └─ 否 ↓
  │
  ▼
网页生成 loginToken（32 位 UUID 去横杠）
网页请求云函数生成小程序码（scene = loginToken）
网页显示二维码，开始轮询（2s 一次，5 分钟超时）
  │
  ▼
摄影师微信扫码 → 打开小程序登录确认页
小程序读取 scene → 调 confirmLogin(loginToken) → 云函数写入 { token, openid, status:'confirmed' }
（若该 openid 尚无 admin 记录 → 顺带隐式建档为摄影师）
  │
  ▼
网页轮询到 confirmed → 换取 sessionToken（有效期 30 天）→ 存 localStorage
  │
  ▼
进入项目列表
```

**异常分支**

| 情况 | 用户看到 | 系统行为 |
|---|---|---|
| 5 分钟未扫码 | 「二维码已过期，点击刷新」 | 生成新 loginToken，旧 ticket 作废 |
| 网页轮询中网络断开 | 「网络异常，正在重试」 | 指数退避重试，最多 3 次后提示刷新页面 |
| sessionToken 过期（30 天） | 自动回到扫码页 | 清除 localStorage |
| 扫码后小程序端 openid 获取失败 | 小程序提示「登录失败，请重试」 | 不写 ticket，网页继续轮询 |

### 1.2 创建项目（F-04）

```
点「新建项目」→ 填项目名*、套餐张数上限* → 提交
  → 项目创建（status=DRAFT）→ 自动跳转到该项目的上传页
```

> **V2 要求：创建后直接进上传页**，不再出现"复制上传码"这一步（G-1）。

**异常**：项目名为空 → 就地提示；重名 → 允许（不校验唯一性）。

### 1.3 上传照片（F-05 / F-06）

```
进入项目上传页
  │
  ├─ 项目已有照片？ → 提示「已有 N 张，继续上传将追加；同名文件会覆盖」
  │
  ▼
拖入文件夹 / 选择文件（支持多选与文件夹拖拽）
  │
  ▼
显示待传列表（文件名、大小、总数）
  │
  ▼
【画质选择 + 预览对比】（F-06）
  - 默认取第 1 张作为样张，可「换一张」
  - 浏览器本地生成四档，左右滑块对比，可 100% 放大
  - 显示：长边像素 / quality / 单张预估体积 / 「这批 N 张 ≈ XXX MB」
  - 选择后锁定档位
  │
  ▼
点「开始上传」
  - 并发 3，逐张：本地压缩 → 上传 preview → 上传 thumb → 调 registerPhoto 登记
  - 进度条：已传 / 总数 / 当前文件名
  │
  ▼
上传结束 → 完成提示（成功 N 张、失败 M 张、占用 XXX MB）→ 引导「邀请模特」
```

**异常分支**

| 情况 | 用户看到 | 系统行为 |
|---|---|---|
| 单张失败 | 列表中标红，提供「重试失败的」 | 自动重试 2 次；仍失败则留在失败列表 |
| 网络断开 | 「网络已断开，已暂停」 | 停止排队，恢复后可继续 |
| 页面刷新 / 关闭 | 重新进入后提示「上次有 N 张未完成」 | 已成功的不再重复传（按文件名去重） |
| 同名文件 | 提示「将覆盖已有 N 张」 | 覆盖（现有行为，保持） |
| 文件不是图片 | 跳过并在结果里列出 | 不上传 |
| 超过在线额度 | 「额度不足，剩余可传 XXX 张」 | 前端拦截 + 云函数二次校验 |

### 1.4 邀请模特（F-07）

```
项目详情 → 点「邀请模特」
  → 生成小程序码（scene 带 inviteToken）→ 显示二维码 + 邀请链接
  → 网页端：可下载 PNG / 复制链接（摄影师自行截图发微信）
  → 小程序端：可直接转发给微信好友/群
```

**规则**：
- 一码一人：一个 inviteToken 只能被一个微信账号使用（现有安全模型，保持）
- 同一项目最多 5 位模特
- 邀请链接有效期与项目存续期一致

**异常**：模特数已达 5 → 提示上限；模特已提交后重复扫码 → 直接进入查看态。

### 1.5 查看进度与结果（F-03 / F-08）

```
项目列表：每个项目显示
  - 状态标签（草稿 / 上传中 / 选片中 / 已提交 / 已归档 / 已过期）
  - 照片数、模特数
  - 每位模特：昵称 + 进度（未��始 / 选片中 12 张 / 已提交 30 张）
  - 剩余存续天数
  │
  ▼
点进项目 → 按模特查看 → 缩略图网格 + 文件名列表
```

### 1.6 导出清单（F-09）

```
结果页 → 「复制文件名」/「导出 CSV」
  - 按文件名升序，一行一个
  - 复制成功后 Toast 提示「已复制 N 个文件名」
  - CSV 含列：序号 / 文件名 / 模特备注名
```

> **这是本项目的差异化核心（G-3）**。导出后摄影师的下一步是回 Lightroom 按文件名筛 RAW。

### 1.7 解锁重选（F-13 / R-2）

```
结果页 → 选某位模特 → 「允许她重新选择」
  → 确认弹窗文案：
     「她将可以在已选的 N 张基础上继续调整（可加可减）。确定吗？」
  → 确认 → locked=false → 状态回 SELECTING
  → 模特下次打开即可修改
```

> **文案必须与行为一致（R-2）**：后端保留原选择（`keep = sel.photoIds`），文案说"在此基础上调整"，**不得**说"清空"。

### 1.8 项目维护（F-10）

| 操作 | 行为 |
|---|---|
| 延期 | `expireAt += 30 天`；若已归档，恢复为 `UPLOADING` 并提示需重新上传 preview |
| 手动归档 | 删除 preview 文件、保留 thumb 与文件名；`status=ARCHIVED`；重算 `usedBytes` |
| 删除 | **先删云存储文件（preview + thumb + 邀请二维码），再删数据库记录**；任一步失败记日志但不阻断 |

## 二、模特完整流程

### 2.1 进入项目（T-M1）

```
微信中点开邀请链接 / 扫邀请码
  │
  ├─ 首次打开（该 openid 无 model 记录）→ 隐式建档 → 进入 guide 引导页 → 开始选片
  ├─ 已建档且曾打开过此项目 → 直接进入相册
  └─ 已建档但第一次进这个项目的邀请 → 建档关联 → 进入相册
```

**异常分支**

| 情况 | 用户看到 | 系统行为 |
|---|---|---|
| 邀请码已被他人使用 | 「该邀请已被使用，请联系摄影师重新发送」 | 不建档 |
| 项目不存在 / 已删除 | 「项目不存在或已被删除」 | — |
| 项目已过期 | 「该项目已过期，请联系摄影师」 | 禁止选片，允许只读浏览（若有权限） |
| 项目已归档 | 「该项目已归档」 | 只读 |
| 模特已提交 | 进入查看态，显示已选列表，**不能改**（R-1） | — |

### 2.2 浏览与选择（T-M2 ~ T-M4）

```
相册网格（缩略图）
  - 点击缩略图 → 进入大图
  - 大图内：左右滑切换、双指缩放、双击放大
  - 大图内：勾选 / 取消（有明确角标）
  - 返回网格：已选项有选中标记
  - 顶部/底部：已选 N / 上限 M
  │
  ▼
选择变更 → 2 秒防抖 → 自动保存到云端
```

**规则**
- 达到套餐张数上限时：禁止再选，提示「最多可选 M 张」（前端 + 云函数双重校验）
- 自动保存失败：保留本地选择，顶部提示「未保存，正在重试」，恢复后自动补存
- 未提交前随时可改

### 2.3 提交（T-M5）

```
点「提交选片」
  → 二次确认：「已选 N 张，提交后将不能自行修改。确认提交吗？」
  → 提交 → locked=true, submittedAt=now
  → 成功页：
      - 明确「已提交给摄影师」
      - 显示已选数量
      - 提示「如需修改，请联系摄影师」
      - 【不提供任何自助修改入口】（R-1，删除现有「继续调整」按钮）
```

**异常分支**

| 情况 | 用户看到 | 系统行为 |
|---|---|---|
| 提交时网络异常 | 「提交失败，请检查网络后重试」 | 本地选择保留，可重试 |
| 重复提交（快速连点） | 第二次被忽略 | 云函数幂等：已 locked 则直接返回成功 |
| 已提交后再进入 | 只读查看态 | — |
| 提交数为 0 | 「请至少选择 1 张」 | 前端拦截 |

### 2.4 解锁后重选

```
摄影师解锁 → 模特下次打开
  → 提示「摄影师已允许你重新选择」
  → 回到选片态，**原有选择保留**（R-2）
  → 可加可减 → 再次提交 → 重新锁定
```

## 三、通知流程（F-14）

```
模特提交成功
  → 云函数检查摄影师是否订阅过「选片完成通知」
  → 有 → 发送一次订阅消息：「{模特名} 完成了《{项目名}》的选片，共 N 张」
  → 摄影师微信内收到 → 点开直达小程序结果页
```

**规则**
- 微信订阅消息为**一次授权一次推送**：摄影师在"发邀请"这一步勾选「选片完成通知我」即为一次授权
- 多位模特 → 每位提交各消耗一次
- 未订阅则不推送，**不做其他通知渠道**（邮件/短信明确不做）

## 四、项目生命周期（完整状态流转）

```
新建 ──▶ DRAFT
           │ 上传第一张
           ▼
        UPLOADING ◀─────────────┐
           │ 模特首次进入        │ 续期（从归档恢复）
           ▼                    │
        SELECTING ──────────────┤
           │ 有模特提交          │
           ▼                    │
     SELECTION_SUBMITTED        │
           │ 摄影师解锁          │
           └──▶ SELECTING       │
                                │
        超过存续期 ──▶ ARCHIVED ─┘
                          │
                       删除 ──▶ （数据销毁）
```

**派生态叠加**：任何状态下，若 `expireAt < now`，页面显示"已过期"标签并限制模特操作；宽限 7 天后惰性触发归档。

## 五、异常场景汇总（每个都必须给出：用户看到 / 系统行为 / 数据状态 / 用户下一步）

### 5.1 上传

| 场景 | 用户看到 | 系统行为 | 数据状态 | 用户下一步 |
|---|---|---|---|---|
| 网络断开 | 「已暂停，等待网络恢复」 | 停止排队 | 已传的已落库 | 恢复后点继续 |
| 单张失败 | 列表标红 | 自动重试 2 次 | 该张未登记 | 点「重试失败的」 |
| 浏览器关闭 | 下次进入提示「上次有 N 张未完成」 | 无 | 已成功的保留 | 继续上传 |
| 重复上传同一文件 | 提示将覆盖 N 张 | 覆盖 | 同名记录更新 | 确认或取消 |
| 额度不足 | 「剩余可传 XXX 张」 | 前端拦截 + 后端校验 | 不变 | 归档旧项目或删照片 |
| 非图片文件 | 结果页列出被跳过的文件 | 跳过 | 不变 | — |

### 5.2 模特选片

| 场景 | 用户看到 | 系统行为 | 数据状态 | 用户下一步 |
|---|---|---|---|---|
| 图片加载失败 | 占位图 + 点击重试 | 重试 1 次 | 不变 | 手动重试 |
| 网络断开 | 顶部「网络异常」 | 保存转本地暂存 | 云端为上次成功值 | 恢复后自动补存 |
| 快速连点 | 无异常（防抖） | 2s 防抖合并 | 最终态正确 | — |
| 自动保存失败 | 顶部「未保存，正在重试」 | 退避重试 | 云端旧值 | 等待或手动重试 |
| 提交时网络异常 | 「提交失败，请重试」 | — | 未锁定 | 重试提交 |
| 重复提交 | — | 幂等返回成功 | 已锁定 | — |
| 超过张数上限 | 「最多可选 M 张」 | 前端拦截 | 不变 | 取消一些再选 |
| 已提交后进入 | 只读查看态 | — | locked | 联系摄影师 |
| 解锁后进入 | 「摄影师已允许重新选择」 | — | 原选择保留 | 增删后重交 |

### 5.3 项目

| 场景 | 用户看到 | 系统行为 | 数据状态 | 用户下一步 |
|---|---|---|---|---|
| 项目不存在 | 「项目不存在或已被删除」 | — | — | 联系摄影师 |
| 项目已过期 | 「已过期」标签，禁止选片 | 到期即限制 | 不变 | 摄影师续期 |
| 项目已归档 | 「已归档」，模特只读 | preview 已删 | thumb+文件名保留 | 摄影师续期需重传 preview |
| 邀请码已使用 | 「该邀请已被使用」 | 不建档 | 不变 | 索取新码 |
| 身份不匹配 | 引导至正确入口 | — | 不变 | — |
| 模特数达 5 | 「最多 5 位模特」 | 拦截生成 | 不变 | — |

## 六、V2 主链路（验收时走这一条）

```
① 打开网页 → 显示小程序码
② 微信扫码 → 网页自动进入项目列表
③ 新建项目 → 填名与张数上限 → 自动进上传页
④ 拖入文件夹 → 画质预览对比 → 开始上传 → 完成提示
⑤ 点「邀请模特」→ 出二维码（可下载 / 可微信转发）
⑥ 模特扫码 → 浏览 → 勾选 → 提交 → 看到「已提交」
⑦ 摄影师收到订阅消息 → 打开控制台 → 看结果 → 一键复制文件名
⑧ 粘进 Lightroom 筛 RAW → 开始修图
```

> 这条链路走通即 V2 达成。链路之外的任何东西都不在范围内（见 `01_PRODUCT_SCOPE.md` 第八章红线）。
