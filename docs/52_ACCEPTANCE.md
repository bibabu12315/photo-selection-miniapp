# 52 · V2 验收标准

> 验收是**按文档验收**，不是按代码验收。
> 实现者说「做完了」不算完成，用例通过才算完成。
>
> 相关文档：`51_TEST_CASES.md`（用例）· `50_TEST_PLAN.md`（策略）· `43_DEV_STATUS.md`（进度）· `53_RELEASE_CHECKLIST.md`（发布）

---

## 一、验收原则

### 1.1 三条铁律

1. **文档是标准，代码是被检对象。** 代码与文档冲突 → 缺陷在实现方，按 `40_AI_DEVELOPMENT_RULES.md` 的冲突上报模板处理。
2. **用例没跑过 = 没做完。** 不接受「逻辑上应该没问题」。
3. **P0 用例不过 = 不能进入下一阶段。** 不能带着已知的 S 级缺陷往下做。

### 1.2 谁来验收

| 阶段 | 验收人 | 方式 |
|---|---|---|
| P0 | 开发 AI 自测 → 你复验关键 5 条 | 用例执行 |
| P1 | 你（人工真机） | 8 条锚点 + 用例 |
| P2 | 你（人工真机） | 用例 |
| P3 | 你（人工真机） | 四态自检表 |
| **最终** | **你，走一遍完整真实拍摄流程** | 见第三节 |

> **最后一条最重要**：最终验收不要用 `TEST-` 项目，用你**真实拍的一组照片**（20~30 张就够），找一个真人模特（朋友/家人）走完整流程。测试数据会掩盖真实体验问题。

## 三、最终验收：8 条锚点

> 来源：`43_DEV_STATUS.md` 第七节。
> **验收方式：用真实照片 + 真人模特走一遍，不要模拟。**

| # | 锚点 | 验收动作 | 通过标准 |
|---|---|---|---|
| 1 | 打开控制台 → 出现小程序码 | 电脑 Chrome 打开控制台地址 | 3 秒内出现码，有倒计时 |
| 2 | 微信扫一下 → 自动进入，看到项目列表 | 用自己的微信扫 | **无需刷新**自动进入；列表有内容 |
| 3 | 新建 → 拖文件夹 → 画质对比 → 上传 | 用真实拍摄的 20~30 张 | 画质预览能 100% 放大；上传有进度；完成有提示 |
| 4 | 生成邀请二维码 → 发给模特 | 生成并截图发微信 | 码清晰；对方能扫 |
| 5 | 模特扫码 → 浏览 → 勾选 → 提交 → 看到「已锁定」 | 让真人模特操作 | 全程**没人教**就能完成；终态页明确；无「继续调整」 |
| 6 | 摄影师收到一次通知 | 模特提交后等 1 分钟 | 微信收到服务通知 |
| 7 | 网页打开结果 → 复制文件名 → 粘进 Lightroom | 实际操作一遍 | 文件名与 DCIM 原名一致、升序；**能直接用于筛选** |
| 8 | 全程没有从手机复制任何东西到电脑 | 回顾整个过程 | 确认无误 |

**第 5 条是 hardest 的一条**：让一个没用过这个工具的人操作，你在旁边**只看不说话**。他说「这里不知道点哪」的地方，就是还没做完的地方。

## 四、验收判定

### 4.1 判定口径

| 判定 | 含义 | 处理 |
|---|---|---|
| **通过** | 全部用例通过，无 S / A 级缺陷 | 进入下一阶段 |
| **有条件通过** | P0 用例全过，有 B / C 级缺陷 | 可进入下一阶段，但缺陷须登记到 `43_DEV_STATUS.md` |
| **不通过** | 任一 P0 用例失败，或存在 S / A 级缺陷 | 打回修复，修完**全量回归**该阶段 |

### 4.2 缺陷与规则的对应

发现缺陷时，先判断它违反了哪条：

```
违反了 30_BUSINESS_RULES.md 的 BR → 至少 A 级（严重）
违反了 01_PRODUCT_SCOPE.md 的红线 → S 级（立即停止并上报）
只是观感 / 文案 / 缺某个态 → B 级
```

**不要靠感觉定级，按这个对照表定。**

### 4.3 「做完了但和文档不一样」怎么处理

这不是验收问题，是**冲突**。按 `40_AI_DEVELOPMENT_RULES.md` 的冲突上报模板：

```
文档要求：...
当前实现：...
冲突点：...
影响范围：...
建议：...
```

在新会话里把这段贴给实现 AI，等它提出方案、你确认后再改。**不要在验收环节直接改代码。**

## 六、验收记录模板

每完成一个阶段，在 `43_DEV_STATUS.md` 追加一条变更日志：

```markdown
### YYYY-MM-DD · P0 阶段验收

**结论**：通过 / 有条件通过 / 不通过

**执行用例**：28 条 P0 中的 X 条（本次涉及 N 条）
**通过**：TC-XXX-NN, TC-XXX-NN
**失败**：TC-XXX-NN（现象：……）

**缺陷登记**
- [A] 描述 → 对应 BR-xxx → 关联任务 T-Px-x
- [B] 描述 → 登记待办

**遗留**：……
**下一步**：……
```

**禁止写「已验收通过」五个字就结束** —— 没有用例编号的记录等于没记录。
