# 30 · 业务规则（V2 唯一规则来源）

> **本文档定位**：把散落在 `00`~`24` 各文档中的业务规则，收敛成一份**带编号、可引用、可验收**的清单。
>
> **给 Coding Agent 的三条硬要求**：
> 1. 实现任何功能前，先在本文件检索相关规则编号。**规则里写了的，照做；没写的，不要自己发明。**
> 2. 规则与代码冲突时，**不得自行修改规则**，按 `40_AI_DEVELOPMENT_RULES.md`（第九轮产出）的格式上报。
> 3. 每条规则标注了「校验位置」。标了「后端」的规则，**前端校验只是体验优化，不能替代后端校验**。

## 十四、规则的优先级

当两条规则看起来冲突时，按此顺序裁决：

```
1. 本文档（30_BUSINESS_RULES）中的编号规则         ← 最高
2. 00 号文档的决策记录 R-1 ~ R-10
3. 01 产品范围（含红线）
4. 20~24 技术设计
5. 10/11 页面与交互规格
6. 现有代码行为                                    ← 最低
```

> **注意第 6 条**：现有代码是**最低**优先级。代码与规则冲突时，**改代码，不是改规则**。
> 唯一例外：若现有代码有明确实现而文档未覆盖（如某个边界处理），按代码现状保持不动并上报。

## 十五、Coding Agent 不得自行决定的事项

以下事项**必须由人拍板**，AI 不得自行选择：

1. 任何**数值上限**（模特数、张数、天数、体积、并发数）
2. 任何**状态值的新增或删除**
3. 任何**价格、收费、额度**相关设计
4. 任何**权限模型的放宽**（如「让模特看到别人的选择」）
5. 任何**红线范围内的功能**
6. 是否**删除现有页面或字段**（倾向保留，除非规则明确要求删除）

> 拿不准时，写清楚「文档要求 / 当前代码 / 冲突点 / 建议」，停下来问。
