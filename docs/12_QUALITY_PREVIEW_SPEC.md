# 12 - 画质预览对比 · 需求与交互规格（F-06 细化）

> 状态：**定稿（2026-10-05）**。本文档是画质预览对比功能的唯一实现依据，与 `10_PAGE_SPEC` / `11_INTERACTION_SPEC` 冲突时以本文档为准（仅限该功能范围）。
> 背景：T-P1-5 第一版采用「单视口 + 滑块分割」形态，实测三个缺陷（见附录 A），已确认返工。

---

## 一、功能目标

上传前让摄影师回答一个问题：**「这批照片用哪一档画质，糊不糊、占多大，我心里有数。」**

三个子目标：
1. 用**真实样张**本地生成四档（不上传、不联网、零云资源消耗）；
2. 让用户**在放大状态下看清档位间的清晰度差异**（这是核心——整体缩略下四档几乎没有可见差异，属正常物理事实，不是缺陷）；
3. 估算这批照片的云端占用体积，辅助决策。

## 二、界面结构

弹窗自上而下四段：

| 区域 | 内容 |
|---|---|
| ① 头部 | 标题「画质预览对比」；操作：换一张样张 / 用这个档位 / 关闭 |
| ② 对比区 | **左右双视口**（等大、并排），各带档位标签（档位名 + 生成分辨率）。两视口显示**同一张样张、同一构图区域、同一显示倍率**，仅档位不同 |
| ③ 缩放工具条 | 「适应窗口 / 100% / 200%」三个按钮 + 当前倍率文字。100% = 以 **A 视口档位的生成像素**为基准 1:1 |
| ④ 档位卡片区 | 四档卡片：档位名 / 长边与 q 值 / 样张实测 KB / 这批 N 张估算 MB。**点卡片 = 选定为上传档位**（不影响视口） |

视口的档位由两个下拉选择（左侧 A / 右侧 B），默认 A=标准、B=原画质（差异最大，第一眼就能看出区别）。

## 三、交互规格

### 3.1 双视口同步（核心规则）

- 两视口**共用一组视图状态** `{ 显示宽度 D, 平移偏移 x, y }`，任何操作同步作用于两侧。
- 两图宽高比相同（同一构图），因此**只要显示宽度 D 相同，构图自动对齐**——不同档位生成像素不同（如 2048 vs 4096），一律拉伸/压缩到同一 D，差异只体现在清晰度上。
- 禁止出现「两视口倍率不同」「A 能看到的地方 B 看不到」的状态。

### 3.2 缩放

- 按钮三档：适应窗口（D = 视口宽）/ 100%（D = A 档生成像素宽）/ 200%。
- **滚轮缩放**：以鼠标位置为锚点（光标下的图像内容缩放前后保持不动），两视口同步。
- 倍率显示：工具条实时显示当前 D 相对 A 档像素的百分比。

### 3.3 平移

- 在视口内按住拖动 = 平移（光标变抓取手），两视口同步。
- 平移范围钳制：图像边缘不允许被拖进视口内超过 0（即不能把图像完全拖丢）。
- 不显示滚动条（`overflow: hidden`），拖动是唯一平移方式。

### 3.4 视觉辅助

- 每个视口左上角悬浮标签：档位名 + 生成分辨率（如「原画质 4096×2731」）。
- 对比区下方常驻提示：样张序号（2/11）、原图分辨率、当前倍率；**首次打开且处于适应窗口时**提示「整体看不出差异是正常的——请切 100% 或 200% 对比细节」。

### 3.5 档位卡片与体积估算

- 卡片数据：长边、q 值、样张实测 KB（生成后测量 blob）、`这批 N 张 ≈ (perMb + 0.025) × N`。
- 点卡片仅改「已选档位」（卡片高亮 + 底部汇总行），**不改动视口 A/B**。
- 「用这个档位」= 确认已选档位，回写上传表单并关闭弹窗。

### 3.6 其他

- 换样张：按 files 顺序循环，重新生成四档，视图状态重置为适应窗口。
- 未选文件时入口按钮禁用（title 提示原因）。
- 关闭弹窗必须释放所有 objectURL。

## 四、技术要点（实现约束）

1. 视图状态单源：`{ mode: 'fit' | '1' | '2', panX, panY }`，渲染函数纯函数化，任何交互只改状态再统一 `render()`。
2. 滚轮锚点公式：`图像坐标 = (光标 - pan) / scale`；`新 pan = 光标 - 图像坐标 × 新 scale`。
3. A/B 两个下拉与视口标签共用数据；切换档位只换 `img.src`，**不动视图状态**（视口不跳）。
4. 图片加载期间标签显示「生成中…」，避免误以为白屏（第一版白块的直接教训）。

## 五、验收用例

| 编号 | 用例 | 通过标准 |
|---|---|---|
| TC-QT-01 | 打开弹窗（默认 A=标准 / B=原画质，适应窗口） | 两视口构图完全对齐；提示文案引导放大 |
| TC-QT-02 | 点「100%」后滚轮缩放、拖动平移 | 两视口始终显示同一构图区域；无白块、无滚动条；不能把图拖丢 |
| TC-QT-03 | 100% 下对比 A=标准 vs B=原画质 | 样张细节处可见清晰度差异（建筑边缘、纹理） |

| TC-QT-06 | 换一张样张 | 四档重新生成，视图重置为适应窗口，标签分辨率更新 |

## 附录 A：第一版缺陷记录（返工依据）

| # | 现象 | 根因 |
|---|---|---|
| A-1 | 适应窗口下左右看不出区别 | 两图被拉到同一显示宽度（≪生成分辨率），浏览器下采样抹平差异；该模式下对比无意义 |
| A-2 | 100% 查看左侧出现大块空白 | A/B 生成像素不同（2048 vs 4096）各自铺开，裁切容器按百分比定位，构图错位 |
| A-3 | 拖动分割线行为怪异 | 拖拽坐标基于 `scrollWidth`，100% 模式页面横向滚动后错位；且点击任意处分割线会跳转 |

**根因结论**：滑块形态要求两侧图像逐像素对齐，而不同档位生成分辨率天然不同——形态本身不成立，故废弃，改双视口同步对比。

## 附录 B：UI 2.0 视觉与层级修复（2026-10-06，用户反馈返工）

### B-1 【Bug 记录】打开上传抽屉后弹窗「变灰」

- **现象**：先开「上传照片」抽屉再点「画质对比」（或反过来），弹窗整体被压灰、不在同一图层。
- **根因**：**不是 z-index 数值冲突，而是弹窗自己的样式整体缺失**。三个 CSS 文件里都搜不到 `.qt-mask / .qt-modal / .qt-head / .qt-bar / .qv-img / .qv-tag / .qt-cards / .qt-card` 等规则（只有 `.qt-duo / .qv / .qt-zoom-*` 五条残留在旧 `console.css`）。`quality.js` 动态创建的 `.qt-mask` 没有任何定位样式 → 按普通 div 排进文档流（页面底部）→ 抽屉遮罩 `.scrim`（fixed，z-40）把它当页面内容盖住。**弹窗根本没有图层，何谈同层。**
- **修复**：补齐全套 `.qt-*` 样式（对照 `web-ui-v2.html` SECTION 10 的 `.qtd-*` 实现，类名前缀换回 `qt-`），`.qt-mask` 必须是 `position:fixed; inset:0` 的真浮层。

### B-2 层级栈（全局唯一标准，写死）

| 层 | 元素 | z-index |
|---|---|---|
| 1 | 照片墙 / 信息栏内浮物 | 2~20 |
| 2 | 抽屉遮罩 `.scrim` | 40 |
| 3 | 上传迷你进度条 `.mini-bar` | 45 |
| 4 | 上传抽屉 `.drawer` | 50 |
| 5 | **画质对比弹窗 `.qt-mask`** | **70** |
| 6 | 大图预览 `.lb` | 90 |
| 7 | Toast | 150 |

画质对比从抽屉打开时：抽屉与照片墙整体压暗、弹窗全亮——它就是比抽屉高一层。

### B-3 【新增】自定义档：单滑条 + 弹窗/抽屉双向互通（2026-10-06 用户需求）

**单滑条定义**（替代上传抽屉里原来的「长边 + 画质」两根滑条）：

- 一根滑条，值域 `0 ~ 300`；**锚点 = 四档常量**：`0=标准(1600/0.75)`、`100=高清(2048/0.82)`、`200=高清Pro(2880/0.90)`、`300=原画质(4096/0.92)`，段内线性插值出 `longEdge` 与 `quality`；
- 滑条旁只显示算出来的 `2400 px · 84%`（只读），用户不直接碰 px 和 q；
- **自定义取值范围收敛为 [标准, 原画质]**——`uploader.js` 里原来 `longEdge≥1200 / quality≥0.40` 的下限作废，clamp 改为 `1600~4096 / 0.75~0.92`；
- 30 文档的四档常量**不变**，自定义只是档位轴上的插值点，落地时同步一句说明。

**互通规则（单源真相 = `PhotoUploader.presets.custom`，禁止存第二份）**：

| 动作 | 行为 |
|---|---|
| 弹窗滑条 input | 写 `presets.custom` → 重新生成自定义档样张 blob → 更新自定义卡（长边/q/实测 KB/批量估算）→ 若 A 或 B 正显示自定义，视口实时刷新 |
| 点「用这个档位」且已选自定义 | `onPick('custom')` → console.js 调 `setCustomSpec` + 抽屉滑条 value 同步 + 自动选中「自定义」卡 |
| 抽屉滑条 input | 写 `presets.custom`（现有 `setCustomSpec` 链路）→ 弹窗再打开时自定义卡显示当前值，滑条位置一致 |

**弹窗 UI 变化**：档位卡从 4 张变 **5 张**（第 5 张 = 自定义，值实时跟随滑条）；弹窗底部滑条常驻（不用先点卡片）；A/B 两个下拉增加「自定义」选项。交互原型：`web-ui-v2.html` SECTION 10。

### B-4 视觉规范（唯一依据：`web-ui-v2.html` SECTION 10）

形态参考 PS「存储为 Web 所用格式（旧版）」：**深色全屏工作台弹窗**（`min(1380px,96vw) × min(860px,90vh)`，背景 `#151513`），照片是绝对主角。沿用本文件第二、三章的全部交互规则（双视口同步 / 滚轮锚点缩放 / 拖动平移 / 钳制），仅视觉按 UI 2.0 Design Token 重做：

1. **视口底部常驻状态条**（PS 同款）：`JPG · q75 · 1600×1067 · 实测 286 KB`，等宽字体，半透明深底——体积信息贴着照片看，不再只藏在下方卡片里；
2. **档位卡片深色化**，选中态用绿描边 + 内圈线（不用大色块），点卡片仍只改「已选档位」不动视口；
3. 视口左上标签（档位 + 生成分辨率）保留，深色胶囊底；
4. 「适应窗口 / 100% / 200%」按钮 + 当前倍率右对齐进工具条；当前模式按钮高亮 `#2E2E29`；
5. 「用这个档位」为浅色主按钮（弹窗内唯一强调色），关闭 × 与换样张为幽灵按钮；
6. 打开时 `body.overflow=hidden`，关闭恢复；弹窗内滚动不穿透。
