## 一、已确认的决策

| 编号 | 决策项 | 结论 | 影响 |
|---|---|---|---|
| D1 | 上传主入口 | **电脑端浏览器上传页**，手机端为辅 | 新增 `web/` 前端工程 |
| D2 | 原图策略 | **不上云**，只传 preview + thumbnail | original 层标记为延后实现 |
| D3 | 模特入口 | 小程序码 + 分享小程序卡片，两者都做 | scene 只放 token |

| D6 | 出片格式 | 相机 **RAW+JPEG 双出**，选片用 JPG，精修回 LR 修 ARW | 预览图来源确定 |
| D7 | 上传页部署 | CloudBase 静态托管（HTTPS 默认域名） | 需配置安全域名 |

## 二、平台硬限制（不可绕过，已核实）

1. **小程序无法访问外部存储。** 小程序运行于沙箱，`FileSystemManager` 只能读写自身目录。SD 卡、OTG 读卡器、U 盘一律读不到。这是设计约束，不是 API 缺失。
2. **选图数量上限。** `wx.chooseMedia` / `chooseImage` 的 `count` 上限为 **9**；`wx.chooseMessageFile` 只能从微信会话中选，上限 **100**，且是平铺列表，无文件夹概念。
3. **web-view 个人主体不可用。** 微信不开放业务域名给个人类型账号。注册个体工商户后可用，是手机端补充上传的唯一绕行路径。
4. **云函数不适合处理大图。** 默认 3s 超时、256MB 内存，处理 18MB 图片极易超时或被杀。图片派生一律放前端。
5. **小程序码 scene ≤ 32 字符。** 与「高熵 token」直接冲突，必须压缩 token 长度。
6. **模特下载只能存相册。** 小程序无文件系统，只能 `wx.downloadFile` + `wx.saveImageToPhotosAlbum`，且需授权。

## 三、修订后的架构

### 3.1 三端职责

| 端 | 载体 | 职责 |
|---|---|---|
| 电脑端上传页 | 浏览器 H5（CloudBase 静态托管） | 拖入文件夹批量上传 JPG 并压缩、上传精修图、查看上传进度 |
| 小程序摄影师端 | 微信原生小程序 | 建项目、看状态、生成小程序码 / 分享卡片、查看选片结果 |
| 小程序模特端 | 微信原生小程序 | 扫码浏览、选片、提交、下载精修 |

### 3.2 上传链路

```
读卡器 → 电脑
   ↓
拖入 DCIM 文件夹（保留相对路径）
   ↓
浏览器 canvas 压缩 + 画水印
   ↓
上传 preview（长边 2048，约 400-700KB）
上传 thumbnail（长边 400，约 30KB）
   ↓
云函数登记 photo 文档
   ↓
ARW 原地留在本地，永不上传
```

300 张的上行量约 150-200MB，电脑端几分钟内完成。云端零图片处理。

### 3.3 图片分层（修订）

| 层 | 是否上云 | 说明 |
|---|---|---|
| original | **否**（延后） | 本地 ARW + JPG，永不上传 |
| preview | 是 | 长边 2048，带半透明水印，模特选片用 |
| thumbnail | 是 | 长边 400，网格列表用 |
| retouched | 是 | LR/PS 导出的 JPG，交付用 |

> 原方案的 preview 长边 2400-4000 偏大，修订为 2048。手机屏幕物理宽度普遍在 1080-1440，2048 已超出 2x 需求。

### 3.4 私有存储的落地方式

1. 云存储权限设为 **「仅创建者可读写」**——客户端之间互相拿不到文件。
2. Web SDK 用 **匿名登录**（`anonymousAuthProvider().signIn()`）获得上传身份，一行代码，无需账号体系。
3. 模特端、摄影师端读取图片一律调用云函数；云函数以 **admin 权限**调 `getTempFileURL` 下发带 `maxAge` 的临时链接。
4. 云存储路径使用随机字符串，不使用可猜测的 `IMG_0001.jpg`。

### photo

```
_id
projectId

stem                 "DSC00123"   ← 与 ARW 同名的关键字段
folderPath           "DCIM/101MSDCF"   ← 文件夹分组
```

> `stem` 与 `folderPath` 是为「选片结果 → 定位本地 RAW」这条链路预留的，务必保留。

### selection（改为项目级单文档）

```

projectId

updatedAt
```

> 原方案按照片逐条存会产生 300 条文档、批量同步写 300 次。改为数组后一次更新即可，更契合文档型数据库。

### upload_session（电脑端上传凭证）

```
_id
projectId

expireAt
createdAt
```

## 五、统一状态机

原方案第 11 节与第 25 节命名打架（`SELECTED` vs `SELECTION_SUBMITTED`、`UPLOAD` vs `UPLOADING`），此处统一，全文以本节为准。

```
DRAFT
  ↓
UPLOADING
  ↓
SELECTING
  ↓
SELECTION_SUBMITTED
  ↓
RETOUCHING
  ↓
DELIVERING
  ↓
COMPLETED
  ↓ （超期）
EXPIRED
```

任何状态下异常退出，重新进入都必须能恢复显示，不允许进入不可恢复状态。

## 六、摄影师工作流（RAW + JPEG）

```
拍摄（ARW + JPG 同时写入 SD 卡）
   ↓
读卡器插电脑
   ↓
上传页拖入 DCIM 文件夹 → 只上传 JPG 派生的 preview/thumb
   ↓
小程序生成小程序码 / 分享卡片 → 发给模特
   ↓
模特选片并提交
   ↓
摄影师在电脑端查看选片结果（文件名清单 + 缩略图 + 文件夹路径）
   ↓
在 LR 中定位对应的 ARW → 精修
   ↓
导出 37 张 JPG
   ↓
电脑端上传页「精修交付」上传
   ↓
模特扫码下载
```

### 6.1 唯一的摩擦点：如何从 JPG 定位到 ARW

JPG 与 ARW 同名不同扩展名（`DSC00123.JPG` / `DSC00123.ARW`），因此 `stem` 字段是天然桥梁。

- **V1.0 做法**：选片结果页提供「复制文件名清单」（每行一个 stem），摄影师在 LR 网格视图按文件名排序，对照清单逐个打旗标（P 键）。选片结果同时显示 `folderPath`，可先按文件夹缩小范围。
- **V1.1 候选**：上传页生成一段复制脚本（Windows `copy` / macOS `cp`），把选中的 ARW 一次性复制到「待精修」文件夹，LR 只导入该文件夹。成本低、收益高。

## 八、Phase 0 清单

### 8.1 环境准备（无代码）

1. 注册**个体工商户**营业执照（多数地区线上免费办理）。
2. 以个体工商户主体注册微信小程序，完成认证。
3. 微信开发者工具中开通**云开发**，得到环境 ID。
4. CloudBase 控制台：云数据库建集合、云存储权限改为「仅创建者可读写」、**安全域名**添加静态托管域名、开通静态网站托管。
5. 小程序后台配置**服务器域名**（若 H5 直连云函数需配置）。

### 8.2 工程初始化（Phase 0 交付物）

1. 微信原生小程序工程 + TypeScript，跑通空白首页。
2. `web/upload.html` 静态页，能在 CloudBase 静态托管域名下打开。
3. 一个测试云函数，验证小程序 → 云函数 → 数据库读写。
4. Web SDK 匿名登录 + 上传一张测试图，验证安全域名配置正确。
5. 云函数 `getTempFileURL` 以 admin 权限下发临时链接，验证私有权限生效。

### 8.3 Phase 0 验收标准

- 小程序能启动、能调云函数、能读写数据库
- 电脑浏览器能打开上传页、能匿名登录、能上传一张图
- 云函数能读出该图的临时链接，未授权路径拿不到链接

## 九、待定与 V1.1 候选

- 二维码 token 定为 **22 位 base62**，scene 只放 token，服务端查表拿 project
- 分享卡片与小程序码两个入口共用同一 token 校验逻辑
- 精修上传采用「点选已选照片 → 上传对应精修」而非文件名自动匹配（Lightroom 导出可能改名）
- 选片清单一键复制 / ARW 复制脚本生成
- 水印参数自定义（文字、位置、透明度、字号）
- 选片数量上限、客户备注、重新开放选片
