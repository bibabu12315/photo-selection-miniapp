## 一、现状诊断（为什么你会觉得"没有区分"）

| # | 问题 | 根因 |
|---|------|------|
| 1 | 你手机上看到"新建项目"，以为没区分 | 区分其实存在，但藏在代码里：你这个微信号绑定了管理员，所以看到摄影师视图；模特是从**分享链接**进入另一个页面的，从来不会看到 home。区分方式太隐晦，没有任何"你是谁"的提示 |
| 2 | 模特没有"主页" | 模特身份绑定在**单个项目**上（一码一人）。她拍了 4 次 = 4 条互不相干的链接，没有统一入口 |
| 3 | 小程序里完全看不出"照片要去网页传" | 上传入口只存在于 project-detail 页的弱提示，且未上传时项目详情几乎是空壳 |
| 4 | 网页上传界面简陋 | 三步表单裸奔（envId 输入框直接暴露给用户）、无进度反馈、无视觉设计 |

**核心结论：V1 是"项目中心"设计，模特只是项目的附属。V2 要改成"双中心"——摄影师有自己的项目工作台，模特有自己的选片工作台。**

---

## 二、V2 产品定位（一句话）

> 摄影师用电脑管理项目 + 上传照片，模特用微信收链接、看图、选片，全程不装 App、不注册账号。

---

## 三、双端逻辑重构

### 3.1 角色定义

| 角色 | 识别方式 | 能做什么 |
|------|---------|---------|
| 摄影师 | 口令绑定（现有 `admin` 机制，保持不变） | 新建项目、邀请模特（每项目≤5）、网页上传照片、查看/导出选片结果 |
| 模特 | 首次点邀请链接时按 openid 自动建档 | 看"我的拍摄"列表（有效期内所有项目）、逐张选片、提交 |
| 路人 | 既非管理员也无模特档案 | 引导页：摄影师输入口令 / 模特从链接进入 |

### 3.2 摄影师端页面流

```
home（我的项目）
 ├─ 项目卡片列表：项目名 · 模特数 · 照片数 · 各模特选片状态摘要
 └─ [+ 新建项目] → project-create
       ├─ 项目名（如"小王的夏日写真-2026.9"）
       ├─ 邀请模特：0~5 位（先建项目，后逐个邀请）
       ├─ 有效期（默认 30 天）
       └─ 套餐张数（可选，见问题③）

project-detail（项目工作台）—— 本次重构的重点页
 ├─ ① 上传区块：状态徽章（未上传 / 已传 N 张）
 │     └─ [去电脑上传] → 弹层显示：网址 + 6位上传码 + [一键复制链接]
 │        （上传码 5 分钟有效，过期可刷新——现有机制保留）
 ├─ ② 模特区块：已邀请 x/5
 │     └─ 每位模特一行：备注名 · 邀请链接/小程序码 · 选片状态（未开始/选片中/已提交）
 └─ ③ 结果区块：按模特分组查看选片结果 → selection-result
```

### 3.3 模特端页面流

```
首次进入（点邀请链接 / 扫码）
  → client-entry：自动校验 token → 按 openid 建模档案（名字由摄影师预先备注，模特不用填）
  → 跳转 model-home

model-home（我的拍摄）—— 新增页面，模特的"家"
  └─ 有效期内的项目列表（按拍摄时间倒序）
      卡片：项目名 · 照片数 · 已选 N 张 · 状态标签（待选片 / 选片中 / 已提交 / 已过期）
      点卡片 → client-select 继续选或查看已选

client-select（选片页）
  保留现有：缩略图网格 + 点选 + 大图 swiper + 2s 防抖同步
  新增：底部常驻栏「已选 N / 上限 M · 提交选片」
  新增：全选本页 / 取消全选（看片 500 张时很需要）

photo-viewer（大图）：保持
selection-result（摄影师看结果）：改为按模特分组
```

### 3.4 路人引导页（新增 `guide`）

无身份用户打开小程序时不再看到空白或报错：

> 「你是摄影师？」→ 输入口令绑定管理员
> 「你是模特？」→ 请使用摄影师发给你的链接或二维码进入

## 四、数据模型变更

```
新增 model 集合：
  { openid, displayName(摄影师备注), createdAt }

新增 invite 集合（替代原来 selection 里的一码一人）：
  { projectId, modelId, token, status, boundAt }
  · 每个项目最多 5 条 invite → 对应"最多分享给 5 个模特"
  · 同一模特被再次邀请时，openid 命中已有 model 档案 → 直接关联，不新建

selection 集合改为双人键：
  { projectId, modelId, photoIds[], locked, submittedAt }
  （原项目级单文档 → 每项目×每模特一份）

project 集合新增：
  { packageCount?: number }   // 套餐张数上限，可选

photo 集合：不变
```

**兼容性**：当前还在审核阶段，库里都是测试数据 → **不做迁移，直接清库重来**（见问题⑥）。

## 五、网页上传改造（诉求③）

小程序端只做"入口和引导"，上传仍在网页（理由不变：微信小程序单次选图 9 张上限，且读不到 SD 卡文件夹结构）。

### 5.1 小程序内的引导（project-detail 上传区块）

- 未上传时：醒目卡片「这一项目前还没有照片 → 去电脑上传」
- 上传中：显示「已传 N 张」
- 弹层给出**完整可复制的网址** + 上传码，摄影师在电脑浏览器输入即可

### 5.2 网页上传页重做（web/index.html）

| 现状 | 改为 |
|------|------|
| 第一步要求手动输入 envId | 隐藏（编译时注入），用户无感知 |
| 三步表单平铺 | 三步向导：①输上传码 → ②拖拽/选文件夹 → ③看进度 |
| 无上传进度 | 每张图进度条 + 总进度（N/M）+ 失败列表一键重试 |
| 无预览 | 上传后缩略图墙（含文件名），确认与 DCIM 同名一致 |
| 无样式 | 视觉与小程序同风格（黑白灰 + 一个强调色），响应式 |

## 六、整体 UI 风格

> **UI 已单独出稿：`UI设计稿V2.0.html`**（浏览器打开，含摄影师端 6 屏 / 模特端 4 屏 / 网页上传 4 屏的实框稿 + 状态清单）。实现以该稿为准。

- **基调**：摄影工具感——黑白灰为主、大留白、图片即主角，强调色只用于"已选中"和主按钮（与截图里的黑色按钮风格延续）
- **摄影师端偏"工作台"**：信息密度高一点，状态一目了然
- **模特端偏"画册"**：大图、沉浸、少文字，选片像翻样册而不是填表

## 八、已确认的决策（2026-10-01）

| # | 问题 | 决策 |
|---|------|------|
| ① | 同项目 5 个模特看到的照片 | **同一批照片**，各自独立勾选，photo 表不加分组字段 |
| ② | 模特回访方式 | **openid 隐式身份**（A+B 结合）：首次通过邀请链接进入时按 openid 建模档案；之后无论点新邀请链接还是直接打开小程序，都按 openid 识别身份，进入 model-home 看到**全部历史项目**。无需模特输入任何东西；换微信号 = 新身份（由摄影师重新发链接即可） |
| ③ | 套餐张数 | **做**。新建项目可设定"最多可选 N 张"，选到上限禁止再勾，底部栏显示「已选 N / 上限 M」 |
| ④ | 提交后能否再改 | **保持现状**：锁定 + 摄影师可解锁（未提出异议，按默认执行） |
| ⑤ | 模特名字 | **由摄影师邀请时预先备注**（如"小王"），模特不填（未提出异议，按默认执行） |
| ⑥ | 旧测试数据 | **清空，不迁移**。审核期数据均为测试数据，新结构直接重来 |

## 九、对 3.3 模特端页面流的修正（基于决策②）

```
打开小程序（任意方式）
  → 静默取 openid
  ├─ 命中 admin            → 摄影师端 home
  ├─ 命中 model 档案       → model-home「我的拍摄」（历史项目全部可见）
  └─ 都没有（路人）
      ├─ 从邀请链接/扫码进入 → 校验 token → 按 openid 建模档案 → model-home
      └─ 直接打开           → guide 引导页（摄影师输口令 / 模特等邀请）
```

要点：**邀请链接只在模特第一次有用**。之后同一个模特再收到新项目的链接，点开后只是"把新项目加进她的列表"，不再重复建档；她也完全可以不点链接、直接打开小程序看到新项目。
